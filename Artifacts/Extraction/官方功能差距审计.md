# 航天基地与烽火地带功能差距审计

审计日期：2026-10-24。审计对象：BrokenEdge 当前源码、项目资产、本地解包资料及本轮运行记录。这里的“官方”指用户提供的本地解包版本；没有把来源文件名当成线上版本说明，也没有用本地验证推断当前官方服务器行为。

## 结论与范围

项目已有能够联机游玩的搜集、交战、撤离、持久化、配装与任务闭环。本轮增加持刀生命周期修复、可追溯保险柜点位、互斥刷新、大厅展示、源物品图标和战术地图。它仍是兼容实现，不能称作完整官方游戏复刻。

“已实现”仅针对表中明确列出的项目能力。“部分实现”表示业务基础存在但内容、规则或表现未对齐。“未实现”限于检查过的模块与入口中没有该能力；“证据不足”表示不能从已取得材料确认官方规则。构建、源数据解析、纯逻辑测试、实际渲染联机和 PIE 的证据分开记录。

## 功能矩阵

| 功能 | 状态及项目证据 | 仍有差距 | 优先级与验收条件 |
| --- | --- | --- | --- |
| 航天基地地图 | 部分实现：`Scripts/SpaceCenter`、`ExtractionRegionStream` 及现有主图／北区／东区 | 完整建筑内部、碰撞、路线和艺术质量不齐；不能把原始 Actor 数量当地图完成度 | P0：逐栋记录楼层、门、楼梯和碰撞，连续步行走通启用物资点，保留视频与路径 |

| 大／小保险柜坐标 | 部分实现：`RestorationEvidence/Loot/SourcePoints.json` 与 `PlacementAudit.json`；36 条源记录分变体，Ma1 启用10个候选 | 两点因缺少可用空间禁用；逐点近距离搜索通过，不等于所有出生点的连续通路均已验证 | P0：恢复支撑空间后启用，不移动原坐标来掩盖地图缺口 |
| 刷新与掉落 | 已实现项目机制：`ExtractionLootLayout` 服务端一次选取、稳定 ID、独立 Recipe；规则和并发搜索验收 | 官方候选关系及掉率证据不足；总裁三选一、H3二选一与内容均明确为项目配置 | P1：补齐源生成器引用链后替换兼容配置；跨变体不混用 |

| AK／SCAR 战斗 | 已实现项目闭环：`ExtractionCombatComponent`、`HitScanWeapon`、`ExtractionItems`；旧 `WeaponMechanicsEvidence/Runtime/Acceptance.json` | 官方精确参数仍有兼容项；本轮没有重新声称测得官方手感 | P1：按 `WeaponMechanicsEvidence/Compatibility.md` 的证据缺口逐项校准 |
| 改枪与附件 | 部分实现：`ExtractionGunsmith`、`ExtractionWeaponVisuals`、装备事务和属性展示 | SCAR 独立全套附件、美术挂点和全枪族数据不齐；大厅预览仅基本主武器 | P1：每个枪族独立兼容表、挂点和瞄具逐项运行检查 |
| 近战 | 已实现本轮修复：`ExtractionMeleeComponent`、`AnimNode_TraversalContact` 与 Knife 验收 | 轻／重伤害及时间仍为项目调参；第三人称使用有记录的源姿势兼容层，不是官方完整状态机 | P0回归：视角重建、攻击、攀爬、倒地、复活、死亡不重复攻击、不残留可见刀；P1补完整动作 |
| 弹药／护甲／生命 | 部分实现：`ExtractionEquipment`、`ExtractionHealth`、穿透／耐久／部位和治疗相关逻辑 | 全部官方弹种、护甲系列、经济与平衡没有齐全版本证据 | P1：源属性对照和独立命中部位矩阵，不能只比较面板数字 |
| 干员技能 | 部分实现：`ExtractionAbilities`、`ExtractionSmoke` 有治疗、烟雾、救援和冷却 | 不是完整干员阵容或官方技能组合 | P2：每个技能明确授权、目标、遮挡、取消、同步及资源代价 |
| AI／Boss | 部分实现：`ExtractionGuard` 的 Patrol／Engage／Search／Return／Dead 服务端逻辑和导航 | 缺少可确认的 Boss 专用完整行为、特殊敌人内容及官方遭遇编排 | P2：独立行为、巡逻区域、警戒传播、战利品和多人稳定性验收 |
| 爆炸投掷物 | 未实现完整撤离装备闭环：本轮检查 Extraction 模块的物品、技能和输入，只有烟雾投放已有明确入口 | 项目通用 Projectile 类存在不代表库存手雷、引信、抛物线、爆炸遮挡已整合 | P2：按物品消耗、服务端抛射、爆炸遮挡和友军规则实现后再宣布完成 |
| 库存／搜刮 | 已实现项目闭环：`ExtractionInventoryComponent`、`ExtractionInteractionComponent`、Slate 网格 | 源容器表现与全图物品种类不足；图标暂只有已确认映射的7张 | P0回归：满包拒绝、旋转、拆分、并发拿取、旧版本请求和关闭搜索后请求不得破坏库存 |
| 大厅／配装 | 部分实现：`LobbyShowcase`、`LobbyWidget`；三维队伍展示、仓库、商店、任务、准备和取消 | 项目棚景与布局；不是源官方大厅。队员暂用相同蜂医外观，主武器展示没有全附件 | P1：同版本完整截图与源场景取证后更新；保持展示不修改库存 |
| HUD／地图 | 部分实现：现有 HUD、`ExtractionTacticalMap`；本人／队友／撤离共用投影 | 轮廓底图不是官方精确楼层图；缺分层、缩放、完整标记交互与官方音效层级 | P1：精确地面投影、楼层切换、多点定位对照，再扩展标记 |
| 观战／结算 | 部分实现：现有同队观战限制、持久化结算和返回大厅 | 无官方完整回放、收益动效与逐页战报 | P1：死亡、撤离、超时、断线分别验证结算；美术不能替代幂等写入 |
| 商店／任务／成长 | 部分实现：`ExtractionProgression` 有购买、出售、接任务、交付、领取与等级经验 | 原型任务／项目价格；不是官方完整任务链、赛季和经济 | P2：版本化配置、任务依赖、溢出和重复领取验收 |
| 制造／拍卖／交易行 | 未实现：现有经济 Action 仅 Buy／Sell／AcceptQuest／DeliverQuest／ClaimQuest，未发现对应制作队列或挂单入口 | 不把商店购买改名为交易行 | P2后续范围：先定订单、锁物品、手续费、取消、幂等与持久化协议 |
| 联机房间／账号 | 已实现项目 LAN 房间、组队、准备和本地持久化身份；`ExtractionAccountComponent`、`ExtractionPersistence` | 不是官方账号、互联网匹配、运营后台、反作弊或全球服务 | P2独立项目：明确服务端信任边界和部署测试，本轮不接入真实官方服务 |

| 全面战场／全部内容 | 本轮范围外 | 保留其他模式入口不代表实现官方全面战场；全枪械／全干员也不在本轮交付内 | 后续另行拆解，避免假入口和空按钮 |
