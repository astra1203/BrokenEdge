# 角色表现配置

WP-14 将身体、专用第一人称模型/动画、武器替代模型与拟合、趴姿动画、头部隐藏、相机偏移、颈部候选骨骼、挂点和护甲/腿部分区收进 `UBrokenEdgeCharacterPresentation`（Primary Data Asset）。角色只通过 `CharacterPresentation` 软引用选择配置，`PostInitializeComponents` 加载并缓存，运行时读 `GetPresentation()`。武器自己的 `UWeaponPresentation` 仍负责枪械差异并优先于角色级回退。

已迁移的资产位于 `/Game/Characters/Presentation`：

| 角色蓝图 | 表现资产 |
| --- | --- |
| BP_EnemyCharacter | DA_EnemyCharacter_Presentation |
| BP_BrokenEdgeCharacter | DA_BrokenEdgeCharacter_Presentation |
| BP_BrokenEdgeCharacter1 | DA_BrokenEdgeCharacter1_Presentation |
| BP_StingerCharacter | DA_StingerCharacter_Presentation |
| BP_StingerCharacter_Repaired | DA_StingerCharacter_Repaired_Presentation |

迁移先使用旧接口导出 5 个蓝图的 19 项配置及世界模型/动画/变换；保留旧字段的中间构建创建资产并写入引用，再移除角色旧字段。新进程重载编译后再次导出，前后 JSON 完全相同。蓝图 Mesh 组件的序列化值保留作编辑器预览，运行时以表现资产为准。原生无配置测试角色使用不加载资源的默认契约；默认骨骼分区维持此前语义。

`FStingerViewWeaponFit` 移入 CharacterPresentationTypes.h，反射名称仍为 `/Script/BrokenEdge.StingerViewWeaponFit`，武器表现资产继续使用同一结构。趴姿资源路径从角色构造函数移出；`ExtractionHealth::Bullet` 使用受击角色所选配置决定护甲槽/腿伤。爬梯按颈部候选顺序选首个有效骨骼，再回退配置的头骨。

`ValidatePresentation()` 与编辑器 `IsDataValid` 检查世界模型/动画、动画骨架匹配、第一人称模型/动画成对、挂点、头骨、伤害分区是否命中实际骨骼、必需第一人称手骨、趴姿资产加载以及拟合模型完整性。错误包含具体字段/骨骼/挂点。PrimaryAssetTypesToScan 配置为 AlwaysCook；这只是打包规则，不等同于完成 Cook 和包内运行验证。

制作脚本通过 Scripts/Stinger/character_presentation.py 的 get_character_property / set_character_property / save_character_presentation 访问配置。新建或复制角色后首次写入会创建独立配置，避免修改另一角色共享的资产；已有未绑定目标资产时拒绝覆盖。configure_view_fit.py 和 promote_view_fit.py 已改为写表现资产，推广脚本继续要求原有视觉审核记录。其他读取这些字段的制作/检查脚本一并更新。

统一任务入口 `Scripts/Extraction/run_editor_task.py`：

- `presentation-audit`：导出当前配置，不保存资产。
- `presentation-migrate`：一次性旧字段迁移入口；当前 5 个已绑定资产只校验，不覆盖。新增角色应通过制作脚本创建配置。
- `presentation-validate`：重新加载、校验并编译保存 5 个角色蓝图，输出状态和配置快照。
- `presentation`：自动化验证资产加载、可替换骨骼分区、缺失挂点报错、运行时模型应用。

运行参数为 `--engine <UE 根目录> --tag <唯一记录名>`。实际结果和未覆盖场景见 [验证索引](验证索引.md)；单玩家 PIE 不代表远端站蹲趴、上下梯、死亡与重新控制全部验收通过。
