# 库存封装、容量测量与日志滚动

基线 `ff2ac32ad` + 本批修改；UE 5.8.4 / 58902052；源码指纹见 [VerifiedSources.json](VerifiedSources.json)。

库存剩余直接写入已收口到候选事务。初始化、溢出补给及死亡掉落先准备对象/候选状态，提交失败销毁新对象；库存与战利品同步提交。Contents 保留原反射属性名及复制标记，生产调用方只取得 const 引用；测试夹具使用仅开发自动化可用的 friend。未迁移或保存二进制资产。

容量测试在独立 Saved 目录构造合法档案、经济回执及关闭对局，提交后重载并逐字段比较。三档为 10/50/100 个档案，每档案 100/1000/2000 条回执，50/500/2000 个关闭对局。详见 [原始容量](BaselineCapacity.csv) 和 [滚动实现后复测](RollingCapacity.csv)。最大档快照 18,352,489 字节；复测 Commit 432.59 ms、Load 448.89 ms。ProcessPeakBytes 是整个 UE 进程累计峰值，不能解读为单档新增内存。

滚动默认阈值 64 MiB 或 128 条记录，保留 3 代，可通过 Game 配置修改。v2 帧增加 SegmentStart 标记，兼容旧 v1。最新完整状态写入 .next 并 Flush/CRC/Validate 回读后，复制旧主日志到代文件、Flush，再以 Windows MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH) 原子替换主日志。与原方案先移走主日志不同，此实现避免正常滚动中的主文件空窗。非 Windows 暂不滚动，保留主日志并警告。启动仍支持主文件丢失时提升合法 .next；损坏段拒绝启动，不自动创建空仓库。

验证：Runtime + StingerTools 编译通过；库存 7/7，装备 4/4，生成生命周期 3/3，持久化 5/5，容量 Stress 1/1。滚动测试覆盖五轮滚动保留三代、三个失败注入点、主文件优先、缺主文件提升、损坏 pending 拒绝及 v1 兼容。未声称日志滚动能限制单条快照增长；WP-10 保留策略尚待确认。

独立双客户端仅通过大厅/账号等 6 项准备检查；加载 SpaceCenter 时超时，观测可用物理内存约 517 MiB、提交余量约 524 MiB。见 [失败记录](NetworkFailure.json) 和 [资源记录](NetworkResourceLimit.txt)。库存双客户端玩法断言尚未到达，不能把这次运行记为通过。蓝图图节点引用全面审计也尚未完成。
