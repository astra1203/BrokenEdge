# WP-13 第二阶段：预测与射击冷却所有权

基线 `6de708a8d`，UE 5.8.4 / CL 58902052。完整边界见 [战斗状态所有权](../../../../战斗状态所有权.md)。

Extraction 不再读取或修改旧 Combat 的 `bLocallyReloading/bCanFire/FireTimer`。本地换弹预测、冷却门闩和定时器由 ExtractionCombat 持有，通用 Combat 入口经模式适配器分派。Character/动画仍使用原查询方法，因此没有修改 RPC 签名、复制属性或蓝图资产。

冷却在发出射击请求前锁定当前模式。Extraction 回调记录武器弱引用，原武器被移除或替换时只释放冷却，不触发新武器的射击或空仓换弹。旧模式回调不能驱动 Extraction。EndPlay 清理本模式定时器和预测；输入取消不会提前解锁射速冷却。服务器 NextShotTime、可靠射击/装填回执与库存事务继续按原协议处理。

新增 `CombatMode.PredictionAndCadenceIsolation` 验证两模式预测和冷却互不覆盖、旧回调不会解锁新模式、到时释放、松开输入不补射、替换武器不继承自动换弹，以及组件 EndPlay 后不再触发换弹。现有 DispatchAndOwnership 保留旧模式空仓换弹、重复完成不再转移弹药、丢枪及 Extraction 不依赖动画通知完成的检查。

最终构建通过（10.12 s）。模式隔离 2、武器 PIE 1、冲刺 PIE 1、输入 PIE 1、守卫 12、库存 7、生命 PIE 1，合计 25 项不同测试通过。本批执行的用例、Run 元数据和失败记录随目录归档；源码指纹为 `VerifiedSources.json`。初次构建修正了既有非 const getter 的调用限定；测试夹具先补齐 BeginPlay/EndPlay 配对，再修正模式切换必须同时处理守卫标记（守卫在没有 GameState 时也启用 Extraction）。这些失败没有被计为通过。

剩余边界：CombatState、备弹兼容快照和武器挂接仍共享；双客户端 150 ms 延迟/5% 丢包、旧模式完整霰弹枪/切枪/死亡矩阵仍未验收。本次本地单元和真实单玩家 PIE 不代替网络认证，也未修改此前已知 ADS 眼线失败的测试门槛。
