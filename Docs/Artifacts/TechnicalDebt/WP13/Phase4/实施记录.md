# WP-13 第四阶段：动作中断与迟到通知

基线 `c84a28bb1`，UE 5.8.4 / CL 58902052。

旧模式的霰弹枪结束换弹通知此前会再次批量填弹，迟到的逐发通知还会使备弹变负；重复切枪挂接通知会把武器切回去，旧切枪结束通知可以解除后续换弹。新增 LegacyLifecycle 用例先在旧实现复现，再修复这些入口：逐发装填只在权威换弹状态、弹匣未满且有备弹时转移一发；霰弹枪结束通知仅结束动作；切枪挂接每次动作只执行一次，结束通知必须匹配当前动作状态。

模式适配器增加 CancelActions。丢枪和死亡先清理本模式输入、预测和待完成动作，再处理武器；Extraction 仍由自己的取消入口清理定时器，不用旧动画通知转移弹药。旧模式 RepNotify 同步切枪完成标记，处理服务器 Idle 早于本地动画结束通知的时序。

## 网络验证

沿用第三阶段的同进程专服 + 双客户端夹具，各 NetDriver 设置 150 ms 发包延迟、5% 丢包。扩展到客户端实际武器槽入口（SelectSecondaryGun / SelectPrimaryGun）、打开背包中断换弹、切枪中死亡，以及重复死亡调用。检查拥有者/观察者状态与弹药收敛，等待动作定时器截止后仍不补弹，死亡后库存清空且每个物品实例只掉落一份、数量与弹匣值守恒。

首次扩展运行在切枪刚结束时立即开火，因举枪冷却尚未结束而停在第 6 步；修正夹具，等待拥有者和服务器都可开火后再发请求。生产冷却规则未改动。第二次完整通过全部 12 个阶段。

## 失败记录与边界

首次单元夹具误用仅初始化步枪备弹的入口，修正为正常 BeginPlay/PickupAmmo 初始化；第二次基线仍稳定复现上述生产问题。两次失败及网络冷却夹具失败均保留。本批未改网络 RPC 签名、资产或持久化格式。

旧模式用例在临时 World 验证实际入口和迟到通知，不能代替真实旧地图动画及双客户端表现验收。网络 PIE 使用同一编辑器进程中的三个 World，独立打包进程、真实大厅、大地图、重连和完整旧模式联机矩阵仍未覆盖。已知第三人称 ADS 眼线问题仍待修复。
