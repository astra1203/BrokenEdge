# WP-13 第三阶段：动作状态独立复制

基线 `ccc829540`，UE 5.8.4 / CL 58902052。状态边界见 [战斗状态所有权](../../../../战斗状态所有权.md)。

ExtractionCombat 新增独立复制的 ActionState，只有私有服务器入口 SetActionState 可以修改。换弹/切枪定时器和射击校验读取自身状态，不再写入或读取旧 CombatState；移除 PublishExtractionCombatState。Character、动画、交互和挂接路径经模式适配器查询状态；旧模式本地切枪预测收回旧适配器。新 RepNotify 处理远端换弹及切枪完成标记，旧 RepNotify 在 Extraction 模式下不驱动表现。

该改动改变组件复制布局，客户端与服务器须更新到同一版本。存档格式、库存事务、射击回执和蓝图资产未改动。

## 网络回归

新增 `CombatNetworkPIE.StateAndAmmo`，命令：

```powershell
python Scripts/Extraction/run_editor_task.py combat-net-pie --engine <UE根目录> --tag <唯一标签>
```

在同一编辑器进程运行一个 Dedicated Server World 和两个 Client World，使用真实 NetDriver/连接。每个 NetDriver 设置 PktLag=150、PktLagVariance=0、PktLoss=5 并断言配置生效；这里的 150 ms 是各端发包模拟延迟，不是测得的完整 RTT。

通过的检查包括：拥有者预测射击后服务器和观察者弹药收敛；所有端观测到 Reloading 后恢复 Idle；换弹前后弹匣加备弹守恒；服务器背包已打开而客户端尚未知情时拒绝换弹，拥有者预测撤销且不增弹；服务器发起切枪后，所有端观测到 Swapping 并在结束时保持武器、弹药及完成标记一致。网络执行报告为成功并带已有资源版本警告，未出现测试断言失败。

首次直接使用生产单人靶场模式时，靶场先进入 Active，正式对局的 PreLogin 因而返回 MATCH_IN_PROGRESS，客户端无法进入。确认日志原因后终止该次测试进程，失败元数据保留。新增的 CombatNetworkTestMode 位于编辑器模块 StingerTools，仅允许测试客户端加入并为出生临时进入 Waiting。测试只在编辑器 World 中覆盖 GameMode，未保存地图、未放宽正式对局加入规则。
