# 独立进程崩溃恢复检查

2026-11-14，基线 `7a8b58d20` 加本批测试改动；UE 5.8.4 / CL 58902052。存储生产逻辑未改。

普通存储 4 个边界（prepared、active、success、death）各执行一次真实进程终止、两次独立重启，共 12 次进程检查通过。经济事务 10 个边界（买入、卖出、任务交付、领奖、撤离结算的提交前/后）同样各执行三次，共 30 次通过。合计 14 次受控强制终止和 28 次恢复测试成功；强制终止的退出码不被当作正常测试成功。

首次普通恢复失败暴露旧断言：回收可复用装备后 Loadout 应保留胸挂、背包、安全箱，不能要求全空。修正断言并增加装备定义/身份检查：退款保留 ID，死亡仅安全箱保留 ID，丢失胸挂/背包补给使用新 ID；步枪不重复，所有物品 ID 有效且唯一。每个边界第二次重启比较第一次恢复的完整档案 JSON，包含物品身份、来源及 Revision，防止再次发放或重复结算。旧失败报告一并保留。

入口：`run_storage_restarts.py --engine <UE> --tag <唯一标签>`；经济增加 `--economy`。两次最终运行分别为 `td_wp18c_storage_20261114_02`、`td_wp18c_economy_20261114_02`。本目录保存运行参数/进程退出码、逐进程事件摘录、普通存储恢复快照及 SHA-256。原始日志在报告所指向的 Saved 目录。

本批验证 Windows 独立进程存储恢复及脚本判定，不代表网络双端完整任务 UI，也不扩展现有保留规则（每档案 1024 回执、全库 128 闭局，活动/来源引用保护不变）。
