# WP-18 遗漏入口补齐与失败判定

基线 `a1e05d4a9`，UE 5.8.4 / CL 58902052。本次复查发现首阶段迁移清单之外还有 5 个 Python 启动入口及 LAN PowerShell 入口。

- `run_network`、`run_pie_lobby`、`run_storage_restarts`、`run_soviet_audit`、`run_nanite_usage` 接入公共引擎定位和运行元数据。错误显式引擎不回退；联机旧环境变量 UE_ENGINE_ROOT 保留为低于 CLI / BROKENEDGE_UE_ROOT 的兼容别名，并提示迁移。
- LAN 脚本支持 `-EngineRoot`（别名 `-Engine`）、环境变量和本地配置；记录引擎、Git、脚本指纹、子进程命令和退出结果。Packaged 分支保持不依赖已安装编辑器；未提供包的引擎来源时明确记为未知。
- 编辑器的 `-game/-server` C++ 联机检查关闭不需要的 Python 初始化，避免编辑器工具插件访问游戏模式中不存在的类型。
- LAN 检查拒绝非零退出码，识别 Success 与中文成功，也拒绝同一日志中混合 Success/Failure。军事地图两步检查在首步完成后保持 running，不能提前写 passed；崩溃恢复入口启动即记录 running 和子进程信息。
- 公共元数据记录继承的三个 UE 缓存路径变量，仅记录这三个允许项，不导出完整环境。

验证：6 项引擎测试通过（15 个 Python 入口 × 缺失/版本不符引擎，共 30 个拒绝场景，均不创建运行目录）；6 项现有 Nanite 清单/备份保护测试通过；7 项 PowerShell 完成判定及错误引擎检查通过。PowerShell 测试直接调用解析后的完成判定函数及实际入口预检，不启动游戏。

本提交尚未给新增入口补齐全部真实 UE 运行。大厅、联机、崩溃恢复与重地图的实际执行结果将继续追加；Nanite 资源修复不因迁移启动脚本而自动执行。资产不变，用户的 BrokenEdge.uproject 修改不在提交中。
