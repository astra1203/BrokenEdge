# 航天基地搜打撤体验差距与实现方案

> 评估日期：2026-10-07。项目：BrokenEdge，UE 5.8.3。代码基线：`ue5.8-20260930` / `d39bc22e5c70a7baff002eb68e8e0c00d61c45cd`。
>
> 目标：只做航天基地这一张地图的搜打撤，尽可能接近官方 PC 端的 UI、枪械改装、物资搜索和完整游玩体验。局内任务不作为建设重点。
>
> 本文是差距评估与后续实施方案。下文“建议”“目标”“验收”均为待实施内容，不代表已经完成。历史功能建设记录见[功能还原评估与实施路线](三角洲功能还原评估与实施路线.md)。

## 1. 为什么已经能玩，仍然与官方差距很大

当前项目已经具备服务器判定的射击、物品转移、搜刮、医疗、死亡掉落、撤离结算、仓库保存、小队和基础 AI，能够跑通搜打撤循环。主要问题集中在：**交互界面仍接近测试工具，物品和枪械内容很少，动作与声音缺乏完整打磨，地图只有局部重建，玩法设施和物资分布尚未形成完整航天基地体验。**

玩家每局反复接触的是开包、搜索、看物品、装附件、瞄准、移动、听声和撤离。这些高频操作的表现和规则深度，比新增一批建筑模型更直接地影响“像不像官方”。下一步应先打磨一条完整可重复的游玩流程，再把同样的质量扩展到整张航天基地。

### 1.2 官方参考的使用边界

官方公开资料可以确认改枪涉及多类附件及多维性能取舍，官方工具站也提供改装方案、枪械属性、物资和航天基地密码房相关入口。[官方武器组装展示](https://www.playdeltaforce.com/events/moddedfirearms/en/)、[官方工具站](https://www.playdeltaforce.com/events/hq/en/m/index.html)可作为能力层面的参考。

上述为国际版官方页面，访问日期为 2026-10-07；部分为历史活动页面，工具站还包含未登录占位数据。**不采用其中的占位数值、活动价格或旧武器数量作为当前国服参数。** 本次没有取得当前官方客户端全部界面的同版本截图、连续操作录像，也未确认本地解包资产对应的完整赛季版本。因此像素布局、搜索时序、精校细则、当前撤离条件和新版地图差异列为参考采样项，不编造为已经查明的官方规则。

## 2. 差距总表与优先级

状态含义：**已有可用**表示指定基础功能有证据；**已有原型**表示逻辑或画面简化明显；**尚未实现**指已检查的当前路径没有该能力；**待实机核实**表示不能仅凭源码或静态截图判断质量。

| --- | --- | --- | --- |

## 3. UI：从文字面板到完整游戏界面

### 3.1 具体差在哪里

当前背包由 `SExtractionInventoryPanel` 绘制，采用 1280×720 参考坐标、58 像素格子、色块和中文名称；具备拖放、旋转、拆分、右键操作等基础交互。问题主要是物品缺少图标和完整信息层级，装备布局与详情表达较少，搜索／错误／等待状态的反馈仍简化。现有缩放代码存在，不能笼统地写成“完全没有分辨率适配”；需要验证不同宽高比和字号下的实际布局。[背包界面源码](../Source/BrokenEdge/Extraction/ExtractionInventoryWidget.cpp)

已有实机画面中的左上行动信息、左下生命弹药、中央宽幅拾取提示仍明显属于原型 HUD。其改善需要同时处理字体、图标、间距、位置、淡入淡出和信息优先级，而不仅是修改颜色。单张截图无法证明全部场景的视觉质量。

### 3.2 怎么实现

1. **先建立参考清单。** 按同一官方 PC 版本记录大厅配装、仓库、局内 HUD、背包、搜索、物品详情、改枪、地图、死亡观战、撤离结算各页面；每页记录默认、悬停、选择、拖动、忙碌、失败状态。缺失资料先标注，禁止混用不同版本当作精确还原。
2. **复用规则，替换展示。** 使用 UMG 组合页面与通用物品格，保留已有 C++ 库存、交互与服务器事务。网格的拖放／命中逻辑可继续复用 Slate；不把交易判定搬到 Widget。UMG 支持 HUD、菜单等可视化界面制作，技术入口见 [Epic UMG 指南](https://dev.epicgames.com/documentation/en-us/unreal-engine/umg-ui-designer-quick-start-guide-in-unreal-engine)。
3. **建立统一显示数据。** 在现有物品定义上补充图标、品质显示、描述、分类和展示尺寸；价格由已有商店规则提供，避免 UI 自建第二份价格表。图标采用统一背景、构图和透明边缘，并记录来源；可用资源不足时，用已导入模型统一渲染缩略图。
4. **打通高频操作。** 对齐参考版本的快捷移动、旋转、拆分、装备／卸下、查看详情、返回／取消；为满包、已被拿走、服务器拒绝提供明确反馈。仓库、出战配装、搜索和死亡物资共用物品格与详情组件。
5. **补齐导航信息。** 先提供正式地图对应的二维底图、玩家位置与撤离标记，再加队友和楼层信息；统一世界坐标到地图坐标的转换，读取现有局内状态。不要直接套用未对齐原点或版本的官方地图图片。

**接口变化方向：** UI 只读取经过授权的展示快照并提交现有物品请求；新增展示字段通常只进入物品定义，不必复制进每个存档实例。新增装备容器、方案或实例状态时，再进行显式版本迁移。

**验收：** 1280×720、1920×1080、2560×1440 与一种超宽比例下关键内容无裁切、重叠，拖放落点正确；关闭面板后输入和鼠标状态恢复；空包、满包、长物品名、旋转物品、断开容器、倒地和死亡均显示正确。按参考截图逐页对照，记录具体差异，不使用主观“还原度百分比”。

## 4. 枪械改装：从三个附件到可操作的改枪系统

### 4.1 具体差在哪里

当前附件槽只有 `Optic / Grip / Muzzle`；右键菜单寻找 AK 后执行安装或拆卸。附件保留自己的 GUID 与来源，已有第一／第三人称模型、挂点、握姿和 ADS 偏移，这是可复用的基础。握把和补偿器分别将散布乘 0.8、0.85，不等于已经实现完整后坐力、操控、稳定性等差异。[物品定义](../Source/BrokenEdge/Extraction/ExtractionItems.h)、[装备操作](../Source/BrokenEdge/Extraction/ExtractionEquipment.cpp)、[阶段 6A](../Artifacts/Extraction/Phase6A.md)

官方展示可确认枪管、枪托、握把、枪口、弹匣、瞄具等附件存在不同效果和取舍，而当前只有少量附件与散布规则。这是系统深度的差距，不能仅靠多导入几个模型解决。[官方附件效果展示](https://www.playdeltaforce.com/events/moddedfirearms/en/)

### 4.2 怎么实现

1. **先把 AK 做完整。** 新建改枪页面，支持三维旋转／缩放、槽位选择、已装与候选配件、前后属性对比、应用／取消。预览使用独立展示对象；点击预览不修改玩家实际库存。
2. **拆开“可安装”和“挂在哪里”。** 在枪械定义中配置支持的槽、接口和依赖；附件定义配置兼容条件、占用位置、互斥关系与效果。替换当前菜单中硬编码的 AK 判断。以枪体、护木、导轨等父子挂载关系支持后续扩展，避免所有配件平铺在枪根节点。
3. **建立统一武器属性计算。** 枪械基础参数叠加附件效果，得到服务器与 UI 共用的计算结果。先实现散布、后坐力与回正、ADS／举枪时间、弹匣容量和换弹时间；射程衰减、弹速等随对应战斗规则一起加入。尚未生效的属性不提前显示为有效加成。
4. **扩充有差异的配件。** AK 首批保留现有三件，并按模型和动画可用性补充枪托、弹匣、枪管／护木及另一种瞄具。每种都验证兼容性、代价、挂载和实战效果，不只堆数量。精校列为第二步深化：先取得当前参考版本的可调项目和效果证据，再配置滑块范围与存档字段，不猜测官方公式。
5. **加入方案保存和应用。** 方案保存物品定义及调校参数，不保存某个实际物品的 GUID。应用时由服务器检查拥有的配件、冲突与库存空间，再一次性完成装卸；缺件明确列出，不凭空生成、不默认自动扣款购买。
6. **用同一规格适配后续枪械。** 每把枪都需要模型、动作、音效、弹药、附件、持枪与瞄准校准、网络及存档验证。先增加与 AK 玩法明显不同的一种武器，通过后再扩内容库；旧模式有武器类不等于适配完成。

**接口与存档：** 从现有 `FExtractionItem`、附件实例和装备请求扩展；预览参数与已应用实例分开。需要新的槽位或调校数据时升级存档版本，明确旧 AK 和三附件的默认映射，保留原 GUID、数量、弹药和来源记录。渲染资源使用软引用按需加载；UE 的 [Data Assets](https://dev.epicgames.com/documentation/unreal-engine/data-assets-in-unreal-engine) 与 [Asset Manager](https://dev.epicgames.com/documentation/unreal-engine/asset-management-in-unreal-engine) 可支撑内容定义、加载和打包管理。

**验收：** 同一方案在预览、第一人称、第三人称、掉落后和重新登录后的装配一致；不兼容、缺件、满包与重复请求不造成物品丢失或复制；属性面板变化与射击散布、后坐力、ADS 时间、弹容等实测一致；换弹、切枪、ADS 过程中手部和瞄具不明显穿插。复用[红点校准方法](../Artifacts/Extraction/OpticCalibration.md)，不能用“红点居中”代替安装几何正确。

## 5. 物资搜索：从固定箱子到有发现感的搜刮

### 5.1 具体差在哪里

当前搜索由服务器按物品顺序推进，每件统一一秒；未揭示物品的名称、数量、弹药、耐久、附件等被清空后再发送给所属玩家。关闭搜索会清除当前搜索计时，已揭示记录按容器保留。基础搜索和隐藏机制已存在，不能写成“尚未实现搜索”。[搜索与交互源码](../Source/BrokenEdge/Extraction/ExtractionInteractionComponent.cpp)

普通容器主要固定生成弹药、医疗包、电子元件和工具；装备箱按等级生成固定护甲与附件，钥匙房也使用固定物资。当前缺少足够的容器种类、区域掉落变化、物品图标和真实外观，以及搜索过程的声音与动画层次。[物资生成源码](../Source/BrokenEdge/Extraction/ExtractionLootActor.cpp)、[阶段 6B](../Artifacts/Extraction/Phase6B.md)

### 5.2 怎么实现

1. **先完成四类样板。** 普通补给容器、医疗容器、武器／装备容器、贵重物资容器各做一套完整的外观、提示、搜索声音和物品分布；这是本项目的首批制作分类，不冒充官方完整分类。随后映射到参考版本的实际容器和散落物。
2. **将硬编码物资改为掉落配置。** 按区域、容器、物品类别配置权重、数量范围、空箱概率和价值区间。服务器在对局初始化或首次生成时确定内容；同一局关闭重开不重抽，多人看到同一批实例。保留固定种子的测试入口以便复现。
3. **补齐搜索表现。** 明确未搜索、搜索中、已揭示、已被取走四种显示状态；揭示前后使用匹配的图标、轮廓和声音。时长先配置化，以当前一秒为回归基线，再按采样资料调整；不要直接假定“越贵越慢”就是官方规则。
4. **扩充物品表达。** 增加名称、图标、品质、占格、用途、参考价值、模型、可堆叠信息，形成常见补给与高价值发现的差别。胸挂、口袋、安全箱和不同容量背包属于容器规则扩展，应明确装备槽、可放类别、死亡归属与迁移，不能只画几个 UI 框。
5. **让地图分布支持选择。** 普通路线提供基本补给，重点房间提供不同物资组合；通过实际路线采样调整搜索耗时、获得价值、暴露时间与撤离距离。贵重物品成为绕路的理由，核心内容无需局内任务解锁。
6. **保留原有事务边界。** 拾取、拆分、旋转、交换、拆附件仍走服务器校验与原子提交。新增掉落必须进入现有 GUID／来源体系；UI 展示价值和稀有度不能提前泄露尚未揭示的实际物品信息。

**依赖：** 物品图标与模型清单、容器资产、音频、区域标识、掉落配置、装备容器定义。首批只覆盖一条代表路线，验证体验后再铺满全图。

**验收：** 两人同时取同一物品只成功一次；搜索中被他人取走、关包重开、离开交互距离、死亡或容器卸载均能正确结束或刷新；未揭示详情不泄露；满包和非法装配不吞物品；固定种子结果可复现，多批随机种子的数量、空箱率和价值分布符合本项目配置；成功撤离、失败与重启后的物品结果正确。

## 6. 支撑搜打撤体验的其他差距

### 6.1 动作、枪感、弹道与医疗

现有撤离射击走服务器当前世界的即时射线，限制武器类型并校验射速、弹药、动作状态；客户端预测表现。旧项目存在延迟补偿相关代码，不代表撤离模式已启用完整历史回溯。[撤离战斗入口](../Source/BrokenEdge/Extraction/ExtractionCombatComponent.cpp)

建议建立“移动—举枪—ADS—开火—换弹—切枪—受击—医疗”的动作优先级与中断表；分开调节镜头后坐力、枪体动作、散布及回正，避免只添加屏幕抖动。先校准 AK 的连续录像、空仓／战术换弹、冲刺转举枪、近墙表现和命中反馈，再扩武器。医疗需要适配自己的手部动作、声音和进度反馈，效果提交继续以服务器为准。

距离衰减、弹速／下坠、穿透场景物体与网络延迟下的命中是独立子项。先用参考距离和装备实测确认目标，再按武器逐项补齐；不把现在的护甲等级穿透误写为已经支持墙体穿透。验收同时比较本地画面、远端表现和服务器结算，包含移动射击、连发、中断与正常／弱网环境。

### 6.2 地图完整度、光照和环境设施

7D 已修复一批材质映射并扩展东侧，但原始材质图有节点缺失，玻璃、水面等仍存在近似；预览和正式地图的曝光／天空响应不同，不能混用截图证明同条件画质。North 当前只有 870 个无碰撞流送实例，东侧以常驻几何加入，尚不能代表完整单图的分区方案。[地图与视觉证据](../Artifacts/Extraction/Phase7D.md)

实施时先建立“参考版本区域—本地源资源—已转换—已接入—可通行—有玩法—已验收”覆盖表，逐区域列出缺口；地图面积完整、可看见、可走到和有内容分别验收。优先选一条室内→室外→搜索点→交战点→撤离路线，固定机位、曝光和画质校准金属、混凝土、玻璃、地面、天空和远景，再复制到其他区域。

门、钥匙房、升降设施、攀越／滑索等先核实参考地图实际有哪些，再制作相应交互与同步。当前 6B 的机密房是项目自建的六米房间，不能记作官方对应房间已经复刻。扩区时同时补齐碰撞、AI 导航、区域标识、搜索点与撤离路线；最终只交付一张完整航天基地，不扩其他地图。

### 6.3 声音与环境反馈

已有枪声和命中声播放入口，但音频包存在、调用存在都不能证明完整声场已适配。[命中扫描武器源码](../Source/BrokenEdge/Weapon/HitScanWeapon.cpp)

先补搜索、揭示、拾取、装卸、开关背包和医疗反馈，再补枪械机械声、室内外射击尾音、不同地表与移动状态的脚步、环境底噪和交互设施声音。使用 UE 声音衰减与遮挡配置，以及区域混响；上下楼辨位需单独设计和试听，不能认为打开遮挡开关就自动解决。[Epic 声音衰减](https://dev.epicgames.com/documentation/unreal-engine/sound-attenuation-in-unreal-engine)、[Audio Volumes](https://dev.epicgames.com/documentation/en-us/unreal-engine/audio-volumes-in-unreal-engine)

验收用固定声源和监听点比较近／远、室内／室外、隔墙／开门、同层／上下层；本地预测和远端同步不得重复播放同一射击。记录实际录音及设置，声音验收单列，不用截图或规则测试替代。

### 6.4 AI、小队与地图压力

守卫目前按视线和距离寻找目标，见敌后停止移动开火，丢失目标后前往最后位置搜索，再回巡逻。应先补警戒反馈、受击反应、掩体选择、换位、脱战与区域巡逻差异，再考虑更多敌人或精英／Boss；角色和规则以选定参考版本为准。[守卫源码](../Source/BrokenEdge/Extraction/ExtractionGuard.cpp)

保留当前轻松配置作为默认体验入口。行为变丰富与反应速度、命中率、伤害分开配置，不通过把敌人变成高伤害定点射手来追求“像官方”。小队侧优先完善队友位置、状态、救援进度、标记和技能反馈；扩展其他干员晚于 UI、搜索和 AK 改枪。

验收覆盖隔墙与烟雾遮挡、楼梯和门、目标倒地／退出、搜索后返岗、掉落和下局重置；轻松配置仍适合逛图。新增战斗区域后重新评估 AI 密度及服务器负载，不能直接把四名守卫测试外推到全图。

### 6.5 撤离、仓库、配装和局外准备

当前已有独立撤离、死亡失败、物资持久化、基础商店与成长。主要差距是入口与界面简化、撤离条件和地点有限、物品用途少，尚未形成完整的出发准备和收益反馈。[阶段 4](../Artifacts/Extraction/Phase4.md)、[阶段 6B](../Artifacts/Extraction/Phase6B.md)

先统一仓库整理、配装预览、准备检查、撤离倒计时与条件提示、战利品清单、价值统计和失败结果，再按参考版本逐点配置撤离的开放、时间及携带条件。计算结果由现有 GameMode／状态／持久化路径产生，UI 不自行结算。

固定价格购买和回收足以支撑本目标，暂不建设玩家交易市场、制造、赛季和商业后台。已有任务保持现状，不新增任务链作为核心装备或搜刮内容的必经门槛。验收一名玩家撤离后其他人继续、撤离中离开范围／倒地、超时、断线与重启，保证结算不会重复入库。

## 7. 流畅度与构建：必须单列的差距

7D 的九轮热身后路线样本 P95 为 11.27～12.72 ms，条件为 Ryzen 5 7500F、RTX 4060 Ti、1080p Medium、Development，同机一个渲染客户端、一个 NullRHI 客户端及专用服务器，环境路线没有 AI。**达标不等于没有卡顿：**九轮共有 27 帧超过 100 ms，最大约 247.27 ms；东侧首访另有约 172.80 ms 尖峰，根因尚未定位。六人四 AI 的功能测试与上述环境性能测试分开，不能宣称六个渲染客户端或全图稳定 60 fps。[完整性能条件与结果](../Artifacts/Extraction/Phase7D.md)

最新人机版本的代码和运行验证已完成，但完整 Server UAT 在 Zen 暂存阶段失败；该轮使用新编译的可执行文件与匹配符号，复用已有 cooked 内容运行。此前 7D 有成功打包记录，这两件事不能混写为“最新版本完整打包已通过”。本机补充记录见 `Saved/Extraction/EasyGuardsRuntime01/Report.json`；该目录被 Git 忽略，不是仓库内的永久验收归档。

后续实施顺序：

1. 修复当前 Zen／暂存链路，重新得到与同一代码、配置和资源版本对应的完整 Client／Server 包；在完成前，重用旧 cooked 内容只能记为临时验证方式。
2. 对首次进入区域、首次打开背包／改枪、首次射击分别采集加载、着色器／PSO、游戏线程、渲染线程与 GPU 时间，先定位尖峰，再选异步加载、预加载、资源预算或流送优化措施。
3. UI 图标、展示武器与附件按需加载并保持合理缓存；大型区域按静态几何、碰撞、导航、玩法状态分开考虑加载时机，防止视觉未就绪、物品重生或玩家踩空。
4. 每阶段同时报告冷启动／首访和热身后样本，列出 P95、P99、最大帧、超过 100 ms 的次数、内存／显存与服务器耗时。沿用同硬件 1080p Medium、路线 P95≤16.7 ms 作为基础目标；改枪 UI、完整单图与战斗压力另取样，不套用旧结论。
