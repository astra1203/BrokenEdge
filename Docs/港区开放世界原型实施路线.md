# BrokenEdge 港区开放世界联机原型实施路线

首版目标是让 **2～4 名玩家在公网合作完成一单港区取车委托**。两位异地玩家用各自的正式账号登录 Windows 打包版，在游戏里找到同一间公开房间。一人可以从修车铺开车去货场，另一人可以步行穿巷接应。任一参与者都能交车，每位参与者的账号各收一份报酬。交付后大家可以留在港区自由活动。以下各项均为待实施、待验收目标。

## 一、从进房到交付

| 环节 | 玩家体验与规则 |
| --- | --- |
| 登录与选房 | 项目运营固定专服，每房最多四人。列表显示房名、在线人数、容量和版本。点击房间即可加入，一人可先自由活动。 |
| 接取委托 | 每房同时开放一单。一人发起并参加，其他在线玩家确认参加，至少两人确认后开单并锁定名单。后加入者可以自由活动，看到当前任务和目标车，从下一单起参加。 |
| 去货场 | 修车铺用车和目标车各有一个驾驶位和三个乘客位。队友可以同车、分乘两车或步行。两人抢同一座位时由专服确认一人入座，另一人可选空座。 |
| 取车与交付 | 通过稳定 ID 识别目标车。提前开走、绕路、停车、换驾驶员都能继续。开错车时给出提示。目标车在交付区停稳后，任一在场参与者可在车外确认。两人同时确认也只结算一单，每位名单成员各得一次报酬。 |
| 车辆失效 | 目标车翻覆、越界或卡住时，参与者可请求重新取车。专服检查条件，将同一目标恢复到货场安全点并同步提示。 |
| 掉线与重连 | 掉线即释放座位。驾驶员掉线时车辆减速停车，队友可接管。原账号重连后在安全位置回到街区并恢复任务资格。队友在其离线期间交付，离线成员仍能从账号记录查到报酬。 |
| 全员离线 | 服务端保存房间任务检查点。用相同房间 ID 重启后，从检查点恢复唯一目标车、委托和参与名单。 |

## 二、工程接入与状态归属

| 模块 | 实施决定 |
| --- | --- |
| 大厅与房间目录 | 增加 `Harbor` 模式，接入模式识别、人数上限和地图旅行。专服使用服务凭据登记公网地址、版本、人数并发送心跳，目录移除过期房间。加入时再次核对容量与版本；目录签发绑定账号、房间和有效期的入场票据，目标专服验证后准入。[现有大厅实现](../Source/BrokenEdge/GameMode/LobbyGameMode.cpp) |
| 账号与余额 | 提供用户名和密码注册、登录、注销及换设备登录。账号接口使用 HTTPS，密码由成熟库加盐哈希。服务端按稳定账号 ID 保存余额及任务记录，每个账号同时只允许一个有效游戏会话。测试服交付独立配置、数据库迁移与凭据配置说明。 |
| 港区世界 | 港区地图指定独立 GameMode 和 PlayerController，地图及依赖纳入打包清单。专服持有车辆、座位、行人、交通、委托与参与名单。客户端请求上车、下车、接单和交付，专服校验距离、占用、资格与任务状态后同步结果。刚加入或重连的客户端也能获得当前状态。[现有启动配置](../Config/DefaultEngine.ini) |
| 角色与镜头 | 复用角色移动和徒步视角，核对原角色对模式与控制器的依赖。本机默认第三人称徒步和追尾驾驶，可切第一人称徒步。蜂医动画继续驱动本机手臂；车外队友看到全身上下车与乘坐姿势。各客户端下车时恢复各自先前的徒步镜头、模型显隐和输入。[现有角色](../Source/BrokenEdge/Character/BrokenEdgeCharacter.cpp) · [蜂医第一人称动画](../Source/BrokenEdge/Character/StingerFirstPersonAnimInstance.cpp) |
| 驾驶 | 从一种驾驶模型起步。驾驶员本地即时响应输入，专服校正车辆状态；乘客和旁观者平滑显示车辆运动。徒步与驾驶的 Enhanced Input 映射由本地控制器切换，乘客可观察和请求下车。[模块依赖](../Source/BrokenEdge/BrokenEdge.Build.cs) · [Epic 车辆模板](https://dev.epicgames.com/documentation/unreal-engine/vehicle-template-in-unreal-engine) |
| 任务与持久化 | 每次委托分配唯一 ID。服务端保存房间、任务阶段、目标车 ID、恢复点及参与账号。在同一数据库事务内完成委托、逐人登记奖励并更新余额，以“委托 ID＋账号 ID”唯一约束保证重试安全。客户端只保存本地设置和登录会话。 |

## 三、可试玩里程碑

每个里程碑都用专服和独立客户端验收。M0 和 M6 需要真实异地网络；开发过程可用同机多进程复现问题。分别记录测试拓扑、构建版本和结果。

| 阶段 | 交付内容 | 放行条件 |
| --- | --- | --- |
| M0 · 异地进房 | 建立灰盒港区、账号服务、公开目录和固定测试房。 | 两个不同外部网络的 Windows 打包客户端分别注册、登录、选房，在同一地图看到对方行走。另测房满、版本不符、票据失效和专服下线时的反馈。 |
| M1 · 同车出发 | 完成车门选点、四个座位、控制与镜头切换，调校加速、倒车、制动和低速转弯。 | 两人抢驾驶位只有一人成功；四人能同车并在停车后换驾驶员。覆盖驾驶员掉线、车门贴墙、两侧受阻、高速请求下车及第一人称视角恢复。连续上下车十次检查输入与镜头。 |
| M2 · 分头取车 | 灰盒搭建修车铺、货场、可环行主路、步行近道、路口和停车区。设置两辆独立车辆，用招牌、吊机及货场入口作为地标。 | 两人分别开车和步行到达货场，再同车返回。第三人途中加入能看到正确的车辆位置与座位。实跑连续三个弯、会车、入场、停车和穿巷，据此调整车速、路宽、镜头与建筑间距。 |
| M3 · 共享街道 | 专服驱动路口车流及行人，支持跟车、让行、过街和避让。 | 一人堵路，队友看到后车停下；移开障碍后双方看到车流恢复、行人继续过街。四人分处街区不同位置运行十分钟，记录卡死、碰撞、位置校正和专服帧时间。 |
| M4 · 合作交单 | 接入委托人、参加确认、目标提示、交付区与按账号发奖。 | 两人和四人分别完成整单。覆盖提前开走目标车、交错车、换驾驶员、两人同时交付、参与者离线后队友交付，以及后来者查看任务但不计入本单奖励。 |
| M5 · 重连与恢复 | 接单、取得目标车和提交交付均有可恢复记录。恢复时使用安全停车位和步行点。 | 在三个时点分别中断客户端或重启专服，核对资格、唯一目标车、余额与奖励记录。验证全员离线后恢复、换设备登录、重复登录，以及数据库暂时不可用后重新交付。 |
| M6 · 公网打包验收 | 打磨上下车动作、驾驶镜头、发动机与路口环境声、目标提示及交付反馈。准备 Windows Development 客户端、配套专服和测试服务。 | 两台异地设备跑通“登录—选房—同车或分头取车—交付—重进核账”。另做四客户端满房回归，并以每方向 50 ms 延迟及 2% 丢包验证抢座、驾驶校正、掉线接管和结算。回归原大厅及搜撤入口。 |

## 四、验收证据与部署条件

- **公网条件。** 项目需要一台外网可达的游戏测试主机、账号与目录服务的 HTTPS 地址，以及可持久化的数据库。具体主机在部署阶段单独指定。
- **验收归档。** 记录客户端和专服版本、启动方式、测试拓扑、操作录像与遗留问题。用同一房间和委托 ID 对照两端画面、专服事件及逐账号奖励记录。性能记录注明机器、分辨率、画质、车辆数与行人数，分别采集首次经过路口和重复绕行的帧时间及网络流量。
- **首版完成条件。** 两位异地玩家无需输入 IP，即可用游戏内列表找到同一房间、合作把正确车辆交回修车铺，重新登录后各自查到恰好一份报酬。四人满房、弱网和恢复场景达到 M6 的验收条件。
