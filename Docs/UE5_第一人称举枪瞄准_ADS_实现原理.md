# UE5 第一人称举枪瞄准（ADS）实现原理

本文说明类似《三角洲行动》的第一人称射击游戏如何实现举枪瞄准，并给出可用于 UE5 的实现路线。

> 本文是通用技术方案，不代表《三角洲行动》的内部实现，也不表示 BrokenEdge 当前已经实现这些功能。文中的组件名、变量和参数均为设计示例，未对本项目源码进行实现核验。

## 1. ADS 的核心是什么

ADS 是 Aim Down Sights，即通过机瞄、红点或倍镜进行举枪瞄准。

它不是单纯把画面放大，而是让枪上的瞄准基准与摄像机视线对齐，并协调动画、镜头和射击方向。

```text
正常持枪：摄像机朝向目标，枪位于画面右下方。
举枪瞄准：枪抬到视线前方，瞄准器中心与摄像机视线对齐。
```

实现时需要解决五件事：

1. 枪和瞄准器应该移动到哪里。
2. 双手如何自然地跟随武器。
3. 举枪和收枪如何平滑过渡。
4. 准星、枪口和弹着点如何配合。
5. 倍镜如何显示放大的画面。

## 2. 摄像机、武器与瞄准基准

### 2.1 在瞄具上定义参考点

可以在武器或瞄具上设置 `AimSocket`，记录瞄准参考位置和方向。这个名称是项目约定，不是 UE 内置的 ADS 功能。

需要明确参考点的语义：

- 如果它表示瞄具中心，摄像机应位于其后方，并保留合适的观察距离。
- 如果它表示理想眼睛位置，则应让它的位置和朝向对齐摄像机。

不要把这两种约定混用，否则容易导致摄像机钻进镜片、眼距不正确或瞄具遮挡画面。

对齐包含位置和旋转两部分。仅把瞄准器移动到屏幕中心，并不保证能沿正确方向看穿瞄具。

### 2.2 两种实现路线

| 路线 | 做法 | 实现时的关注点 |
| --- | --- | --- |
| 调整枪和手臂 | 摄像机保持相对稳定，武器移动到视线前方 | 需要让手臂和武器一起调整 |
| 调整摄像机 | 摄像机移动到瞄具后方的观察位置 | 避免武器动画直接造成过大的镜头晃动 |

也可以混合使用。第一版可以先采用摄像机稳定、调整第一人称枪械和手臂的方式。

### 2.3 为什么每个瞄具都需要独立参数

机瞄、红点、高倍镜的安装高度和观察距离不同。更换瞄具后，枪械需要移动的距离也可能改变。

可以为每种瞄具配置：

| 参数 | 作用 |
| --- | --- |
| 瞄准参考变换 | 确定对齐位置和方向 |
| 观察距离 | 控制眼睛与瞄具之间的距离 |
| ADS FOV | 控制瞄准时的世界视野 |
| 举枪与收枪时间 | 控制过渡速度 |
| 灵敏度参数 | 调整瞄准时的输入响应 |

如果支持侧瞄，可以配置第二组参考变换，在不同瞄准模式间切换。

## 3. 如何让枪真正对齐摄像机

计算时，应先把摄像机目标和瞄具参考点转换到同一个坐标空间，例如第一人称手臂组件空间。

逻辑顺序是：

```text
读取当前瞄具的参考变换
        ↓
确定相对摄像机的理想观察位置与方向
        ↓
计算武器需要施加的旋转与位移
        ↓
应用到武器的驱动节点或持枪手骨骼
        ↓
通过动画和 IK 调整手臂
```

必须同时考虑旋转和位移。旋转武器会改变瞄具的位置，因此不能只用一次世界坐标位置相减代替完整的变换求解。

可以先手动调出一把枪的 ADS 相对变换，验证完整流程，再升级为根据瞄具参考点自动求解。

还要明确谁驱动谁：

- 武器绑定右手时，应通过右手或上游骨骼调整带动武器。
- 武器由独立节点驱动时，可以让双手通过 IK 跟随武器上的握持点。

避免同一帧中同时让武器追随右手、右手又追随武器，产生循环依赖或重复偏移。

## 4. 动画、IK 与 Aim Offset 的分工

### 4.1 动画负责主要动作

准备正常持枪和举枪瞄准两种姿势，或制作专门的举枪动画，完成抬枪、肩部和肘部的主要运动。

仅使用位置插值通常难以表现完整的人体动作；仅使用固定动画又难以精确适配所有枪械和瞄具。因此可以采用“基础动画加程序化修正”的组合。

### 4.2 IK 负责握持约束

IK 用于让手掌保持在武器的握持位置。例如以右手驱动武器，再通过左手 IK 让左手贴合护木或前握把。

FABRIK、Two Bone IK 等可以承担手臂调整，但 IK 本身不会自动完成瞄具对齐。需要先定义正确的目标与坐标空间。

### 4.3 Aim Offset 不等于 ADS

| 系统 | 主要解决的问题 |
| --- | --- |
| Aim Offset | 角色朝上、朝下等方向瞄准时的姿势变化 |
| ADS | 从正常持枪切换为通过瞄具观察，并完成视线对齐 |
| 手臂 IK | 手掌与武器握持点保持接触 |
| 后坐力与晃动 | 在基础姿势上叠加动态偏移 |

Epic 的 Aim Offset 教程展示了根据瞄准方向混合姿势的做法，不能把它直接视为完整的第一人称 ADS 系统。

## 5. 用 ADSAlpha 统一驱动过渡

定义 `ADSAlpha`：

- `0`：正常持枪。
- `1`：完全举枪瞄准。
- 中间值：处于切换过程。

按住右键后向 `1` 过渡，松开后向 `0` 过渡。

```text
瞄准输入
   ↓
目标瞄准状态
   ↓
ADSAlpha
   ├─ 武器位置与旋转
   ├─ 瞄准动画权重
   ├─ 摄像机 FOV
   ├─ 输入灵敏度
   └─ 移动速度与晃动参数
```

示意逻辑如下，不是可直接粘贴编译的完整代码：

```cpp
TargetAlpha = bWantsToAim ? 1.0f : 0.0f;
ADSAlpha = MoveTowards(ADSAlpha, TargetAlpha, DeltaTime / TransitionDuration);

CurrentFOV = Lerp(HipFOV, ADSFOV, ADSAlpha);
CurrentLocation = Lerp(HipLocation, ADSLocation, ADSAlpha);
CurrentRotation = Slerp(HipRotation, ADSRotation, ADSAlpha);
```

其中 `MoveTowards` 表示限制单帧步长、到目标后停止的辅助逻辑；`TransitionDuration` 必须大于零，位置和旋转端点必须在相同坐标空间中。举枪与收枪可以采用不同时间，曲线还可以控制前慢后快等节奏。

UE 中可以用 Timeline、曲线或逐帧插值完成过渡。`FInterpTo` 表现为逐渐逼近，不应把它的速度参数直接解释为固定完成时间。

例如把世界 FOV 从 `90°` 调整到 `65°` 会产生放大感，但这只是演示参数，不代表某种倍镜的精确倍率。

## 6. 准星方向与枪口方向如何配合

### 6.1 摄像机和枪口不在同一个位置

摄像机看得见目标，不意味着枪口到目标之间没有障碍。例如角色贴着墙边时，眼睛可能已经探出去，枪口仍然被墙挡住。

一种便于实现的方案是：

1. 从摄像机沿屏幕中心方向检测，得到期望目标点。
2. 没有命中时，使用该方向上预设最大距离处的点。
3. 从枪口朝目标点进行命中检测，或者发射实体子弹。
4. 枪口路径存在障碍时，优先命中障碍物。

```text
摄像机 ──────────────────→ 期望目标点
枪口   ──→ 墙体
           实际先命中墙体
```

UE 的 `Line Trace` 可以完成射线检测。应合理设置碰撞通道并忽略自身角色和武器，避免检测首先命中自己的模型。

### 6.2 实体弹道需要额外规则

上述方案是一种玩法选择，并非所有射击游戏都必须这样处理。

如果子弹有初速度、重力和飞行时间，简单朝摄像机命中点发射并不能保证远距离命中该点。系统还需要确定：

- 是否根据归零距离调整发射角度。
- 是否保留近距离的瞄具与枪管高度差。
- 后坐力和散布如何影响实际发射方向。
- 武器晃动只是视觉表现，还是也会影响弹道。

瞄具画面和弹道规则需要一致，否则容易出现视觉上对准了目标、实际子弹方向却无法解释的问题。

## 7. 红点与高倍镜如何显示

| 类型 | 可采用的显示方式 |
| --- | --- |
| 机瞄 | 对齐枪械模型中的照门与准星 |
| 红点 | 对齐瞄具，使用材质或其他渲染方式显示瞄点 |
| 整屏放大 | 缩小主摄像机 FOV |
| 镜内放大、镜外保持原视野 | 额外渲染放大场景，并限制在镜片区域显示 |

红点若要表现随观察角度变化的效果，需要专门设计材质与视差表现，不能简单认为把一个点贴在镜片上就能得到完整效果。

高倍镜可以用 `SceneCapture2D + Render Target` 制作原型：

1. 设置用于镜内画面的采集视角。
2. 采用更小的 FOV 获得放大画面。
3. 将结果写入 Render Target。
4. 通过瞄具材质显示在镜片区域。
5. 根据眼睛位置添加遮罩、暗边等表现。

额外采集通常会增加渲染开销，需要控制分辨率、更新频率和参与渲染的对象，并验证镜内外方向一致。没有使用倍镜时可以停止不必要的采集。

## 8. 第一人称与第三人称表现

第一人称看到的手臂和枪械，需要针对玩家视角调整；其他玩家看到的全身角色，需要保持外部观察时的动作合理。

可以使用独立的第一人称手臂，也可以采用全身第一人称方案。不能只为了本地瞄具对齐，把所有玩家看到的武器位置都强行改成同一个视觉偏移。

在联机方案中：

- 本地立即响应输入，更新镜头、FOV 和第一人称动画。
- 将需要影响其他玩家或规则的瞄准状态交给服务器处理和同步。
- 远端角色根据同步状态表现第三人称瞄准动作。
- 射击和伤害遵循服务器权威规则，不能仅凭客户端报告目标就认定命中。

通常没有必要每帧同步本地的 `ADSAlpha`；可以同步状态或必要的时间信息，让各端自行过渡，具体取决于玩法对时序一致性的要求。

## 9. 建议的最小实现顺序

1. 选择一把枪和一个固定瞄具。
2. 建立正常持枪与 ADS 两组目标变换。
3. 用右键和 `ADSAlpha` 实现举枪、收枪。
4. 调整位置、旋转和观察距离，让瞄具对齐。
5. 添加动画与手臂 IK，保证双手握持正确。
6. 加入摄像机目标检测和枪口路径检测。
7. 加入适当的 FOV 与灵敏度变化。
8. 最后扩展到换镜、倍镜、后坐力、呼吸晃动和贴墙收枪。

这一顺序先验证完整操作流程，再增加视觉复杂度，有利于区分对齐问题、动画问题和弹道问题。

## 10. 实现后的验证清单

- 平视、抬头和低头时，瞄具是否仍能正确对齐。
- 连续快速按下、松开瞄准键时，过渡是否连续。
- 更换瞄具后，观察距离和瞄准方向是否正确。
- 行走、跳跃和后坐力叠加后，双手是否脱离武器。
- 贴墙开火时，是否正确命中枪口前的障碍。
- 近距离和远距离的弹着点是否符合既定弹道规则。
- 本地第一人称与远端第三人称是否都表现合理。
- 倍镜开启与关闭时，帧时间变化是否在目标预算内。

本文件仅整理原理和实施建议；文档结构检查不等于已经完成 UE 编译、动画蓝图或运行时验证。
