# 房间列表与准备大厅

## 玩家操作

1. 启动游戏进入 `Lobby`，菜单自动搜索房间；点击“刷新房间”可以重新搜索。
2. 列表显示本项目发现的专服房间，包括不同游戏模式、房间名称、人数和延迟。点击对应行的“加入房间”，只加入该房间，不会自动加入搜索结果中的第一个房间。
3. 加入后显示准备大厅：玩家列表、每人的准备状态、房间人数和游戏模式。
4. 点击“准备”后，按钮变为“取消准备”。所有有效玩家准备且达到最低开局人数后，服务器启动 3 秒倒计时。
5. 倒计时中有人取消准备、新玩家加入或玩家退出，会取消当前倒计时。重新满足开局条件后重新计时。
6. 倒计时完成后，服务器开始在线会话，按房间模式无缝跳转到 `FreeForAll` 或 `Teams`；准备界面自动移除，恢复游戏输入。

本次沿用当前分支的专用服务器架构。客户端没有创建监听服务器的按钮。默认最低开局人数为 2 人，无需等房间满员；专服自身不占玩家人数。

“所有房间”指当前在线子系统搜索到的本项目房间。项目使用 `OnlineSubsystemNull`，对应局域网发现；列表不会自动变成互联网服务器目录。搜索结果是刷新时的快照，房间人数可能随后变化；加入失败时可以重新刷新选择。

## 服务器配置

继续使用 `Config/DefaultGame.ini` 中的设置：

```ini
[MultiplayerSessions.DedicatedServer]
NumPublicConnections=8
MinPlayersToStart=2
MatchType=FreeForAll
bAutoStartSession=True
```

`MinPlayersToStart` 为人数下限，`NumPublicConnections` 为容量。`bAutoStartSession=False` 会禁用自动开局，并在准备界面显示原因。

启动参数可以覆盖人数和模式；新增可选 `-RoomName="房间名称"`，列表会附加会话 ID 的末六位以区分同名房间。未指定名称时使用 `BrokenEdge <模式>`。

两台专服使用不同游戏端口时，可以同时开设不同房间，例如 `-port=7777 -MatchType=FreeForAll` 和 `-port=7778 -MatchType=Teams`。

## 实现位置

| 文件 | 职责 |
|---|---|
| [Menu.cpp](../Plugins/MultiplayerSessions/Source/MultiplayerSessions/Private/Menu.cpp) | 构造房间列表、刷新、保留搜索结果、加入所选房间、恢复失败后的按钮 |
| [SessionRoomRow.cpp](../Plugins/MultiplayerSessions/Source/MultiplayerSessions/Private/SessionRoomRow.cpp) | 每个房间的信息与加入按钮 |
| [SessionWidgetStyle.h](../Plugins/MultiplayerSessions/Source/MultiplayerSessions/public/SessionWidgetStyle.h) | 房间列表与准备界面的原生 UMG 布局和样式 |
| [LobbyWidget.cpp](../Source/BrokenEdge/UI/LobbyWidget.cpp) | 玩家名单、准备按钮、倒计时和服务器状态提示 |
| [BrokenEdgePlayerController.cpp](../Source/BrokenEdge/PlayerController/BrokenEdgePlayerController.cpp) | 本地显示/移除 UI，通过所属控制器提交准备 RPC |
| [BrokenEdgePlayerState.cpp](../Source/BrokenEdge/PlayerState/BrokenEdgePlayerState.cpp) | 服务器修改并复制每位玩家的准备状态 |
| [LobbyGameState.cpp](../Source/BrokenEdge/GameState/LobbyGameState.cpp) | 复制房间设置和倒计时，使所有客户端看到一致的大厅信息 |
| [LobbyGameMode.cpp](../Source/BrokenEdge/GameMode/LobbyGameMode.cpp) | 校验准备请求、开局人数与全员状态，倒计时后开始会话并跳图 |

界面由 C++ 构建为 UMG 控件，不需要手动制作或绑定新蓝图。现有 `WBP_Menu` 的 `MenuSetup` 入口继续生效，运行时使用新的列表布局。`LobbyGameMode::InitGame` 保证旧大厅蓝图保存的基础 `GameState` / `PlayerState` 配置不会阻止新状态的复制，同时保留现有玩家控制器蓝图。

准备 RPC 不接受玩家 ID 参数；服务器只允许调用方修改自己的状态。开始会话的异步回调还会重新检查全员准备条件，避免回调期间有人取消准备却继续开局。观战和失活 PlayerState 不计入开局玩家。

## 验证方法

在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Test-LanSessions.ps1
```

需要实际渲染并保存界面截图时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Test-LanSessions.ps1 -Render
```

脚本先验证空列表和重复刷新，再同时启动两个不同模式的专服房间，使用两个独立客户端点击选定房间，验证默认未准备、准备状态复制、取消全员倒计时、再次准备、模式跳图、会话保留和准备 UI 移除。分别执行 `FreeForAll` 与 `Teams`。日志和可选截图位于 `Saved/SessionTests/Dedicated-<时间戳>/`。

自动化测试从插件移到游戏模块的 `Source/BrokenEdge/Tests/SessionLobbyTests.cpp`，测试名称仍为 `MultiplayerSessions.LAN.MenuFlow`；游戏模块能够同时访问会话菜单和项目的大厅网络状态。

此脚本使用独立进程执行真实 Find → 点击行按钮 → Join → ClientTravel，不依赖 PIE 的预连接。使用 `-Packaged` 时需要先重新构建并打包，旧的 `Packaged` 产物不会自动包含新功能。
