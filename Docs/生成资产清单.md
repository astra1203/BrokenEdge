# 生成资产与覆盖保护

WP-15 的原生 Widget 生成器先检查整个目标集合，再允许任何树修改。版本化旁路文件位于 `Config/GeneratedWidgets/<Game 相对包名>.json`；仅在对应资产保存成功后写入。快照包含父类、根节点、节点类/父节点/顺序、可编辑非 transient 属性及 Slot 布局，差异显示字段和前后值。

无基线、无效基线或与上次生成结果不同，默认拒绝重建。**现有 10 个 Widget 尚无可信历史生成基线，默认生成命令会拒绝，而不是将当前手改自动认作生成结果。**首次重建需先审阅资产；确需覆盖时显式加 `--force`。这会覆盖当前生成区域，生成成功后建立基线。自动化测试临时写入的旁路文件会恢复/清理，不作为生产基线。

源文件均在 `Source/StingerTools/Private`。入口示例：

```powershell
python Scripts/Extraction/run_editor_task.py inventory-widgets --engine <UE根目录> --tag <唯一名>
python Scripts/Extraction/run_editor_task.py extraction-widgets --engine <UE根目录> --tag <唯一名>
python Scripts/Extraction/run_editor_task.py widgets-validate --engine <UE根目录> --tag <唯一名>
```

仅前两个生成任务接受 `--force`；对应原生参数为 `-ForceGeneratedWidgets`，会记录覆盖差异。统一任务成功生成后自动启动新的编辑器进程，重新加载、编译并校验 11 个资产。直接运行旧 Python 脚本不具备这个自动二次进程，应另跑 widgets-validate。

本阶段没有强制重建生产界面，也没有把九个现有生成子 Widget 改成可自由手工维护的资产。后续需要先确定美术可编辑部分，再拆分独立子 Widget；保护范围是 WidgetTree，不包括 Blueprint Graph 或主界面 CDO 类绑定的手工改动。失败默认保留资产；保存部分成功后出现 I/O 错误时不承诺跨多个资产原子回滚，应检查任务记录及 Git 差异。
