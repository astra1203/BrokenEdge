# 任务稳定 ID 与 v9 存档

任务定义包含 QuestId、Type、Prerequisites、MinimumLevel；状态采用带 QuestId 的数组，数组顺序只影响遍历和显示，不决定身份。请求、回执签名、HUD、结算消息和任务页都按 ID 查找；目标行为按 Extract / KillGuards / DeliverFiles 分派。

| 历史索引 | 固定 ID | 目标 | 前置 | 等级 |
| --- | --- | --- | --- | --- |
| 0 | FirstExtraction | Extract | 无 | 1 |
| 1 | ClearGuards | KillGuards | FirstExtraction | 2 |
| 2 | RecoverFiles | DeliverFiles | ClearGuards | 3 |

配置允许最多 256 个任务，检查 ID 唯一、未知前置、重复前置、依赖环和奖励范围。撤离目标支持多次累计；文件提交目前要求 Target=1，保留一次提交一份的既有语义。新增任务在旧档首次接取时建立状态，不重置其他任务。任务页每页显示三行，滚轮可访问新增任务；行号只是显示序号。

更改定义顺序或添加新 ID 不迁移已有进度。删除/改名已有 ID 会令旧状态校验失败，必须另写显式迁移；不能通过调整数组顺序替代迁移。任务配置和客户端/服务器代码需保持一致。

存档版本升为 9：v3～v8 仅在历史读取器内保留三槽位置校验；升级时按上表固定映射，与当前任务定义排序无关。v1/v2 先走原有迁移到三槽历史结构，再转稳定 ID。原日志在修复尾部、恢复和迁移前备份为 Store.journal.v<旧版本>.bak；备份失败不迁移。v9 提交经同一候选校验、追加、刷盘和内存替换协议完成，日志滚动与待提交分段恢复使用 CurrentVersion 上界。

迁移不修改余额、经验、任务标志、进度、文件资格或物品身份；每档案 Revision 加一。新请求签名以 q9 开头并包含 QuestId；旧版请求/旧回执重试会被拒绝，客户端刷新后发起新请求，不会因为协议变化重复领奖。既有回执不改写，仍按 WP-10 窗口保留。

回归覆盖定义重排、新增第四任务、状态重排、未知/重复 ID、依赖环、两次撤离目标、重复领奖请求、真实无 QuestId 的 v8 日志、逐字节备份、文件来源保留、备份/提交失败及重启重试。验证记录见 [验证索引](验证索引.md)。本阶段未执行双客户端 RPC/完整三局流程，以及任务分页的真实鼠标视觉验收。
