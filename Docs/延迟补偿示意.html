延迟补偿是怎么做的

射手画面里的敌人，大约是一个单程延迟之前的位置；开枪请求传到服务器，又过了一个单程延迟。服务器把命中检测用的敌人姿态倒回射手开枪时看到的那一刻，再判断子弹有没有打中。倒带有上限，延迟太高的玩家就得自己提前量。

一发子弹经过的五步

  1. 服务器每帧记录姿态

    每个玩家角色在服务器上每帧记下物理资产各 Body 所属骨骼的世界变换，保留最近 0.5 秒（至少比倒带上限多 0.1 秒）。只存变换，不复制网格。

    LagCompensationComponent · SaveFrame / EnsureShapes
  2. 客户端开枪，带上画面时间

    客户端立刻生成一颗本地预测子弹，只做表现，不结算伤害。同时发送开枪请求，附带 ViewTime = 服务器时间 − 单程延迟，即“我看到的是服务器哪一刻的世界”。

    ExtractionCombatComponent · RequestShot → ServerRequestShotVersioned
  3. 服务器核验并算出倒带时长

    先核验武器、弹药、射速和瞄准方向。倒带 = Now − ViewTime，再限制在 MaxRewindMs（默认 200 ms）和 ping×1.5+50 ms 两者中较小的一个以内，防止伪造时间。

    ExtractionCombatComponent · ServerRewindFor
  4. 服务器子弹逐步飞行

    子弹每 1/120 秒前进一步。主扫掠忽略所有玩家角色，只检测场景；角色改用“本步时刻 − 倒带时长”的历史姿态，对胶囊、盒子、球做纯几何检测，谁更近算谁。

    ExtractionBullet · Tick → ULagCompensationComponent::TraceWorldAt
  5. 判定并同步结果

    命中的骨骼决定部位：Head 走头盔，Hips / Spine 系列走护甲，其余算四肢。伤害由服务器结算，再同步回所有客户端。

    ExtractionHealth · ArmorSlotForBone

示意参数：敌人横移 5 m/s，距离 25 m，子弹 600 m/s，躯干命中半径约 35 cm；横向距离压缩显示。客户端画面落后按单程延迟估算，实际还有少量插值延迟，ping×1.5+50 的余量就是留给它的。时间单位都是毫秒（服务器时钟）。

不倒带的情况

  • AI 守卫开枪 它们本来就在服务器上，没有延迟
  • 主机本地玩家开枪 画面就是服务器当前状态
  • 客户端的预测子弹 只播放特效，不参与结算
  • 死亡或关闭了碰撞的角色 不参与倒带检测
  • 延迟超出上限的部分 不补偿，射手需要自己提前量
