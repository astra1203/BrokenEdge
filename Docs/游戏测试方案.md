# BrokenEdge 游戏测试方案

适用版本：2026-09-09 当前工作区。测试对象为 UE 5.5.4 项目的输入、角色视角、武器战斗、联机同步、房间与准备大厅。

本文是执行方案，不是测试通过报告。用例初始状态均为“未执行”；源码存在、编译成功、动画播放、断点命中都不能单独证明完整功能正确。最终要核对玩家画面、服务器状态、客户端状态和日志。

## 1. 先跑一遍：约 10 分钟的快速测试

这套流程适合每天改完代码后执行。第一次配置环境、启动编辑器和编译的时间另计。

1. **准备版本**：保存资产。如果修改过 `UCLASS`、`UPROPERTY` 或类布局，先关闭编辑器，正常编译后重新打开，避免拿热重载残留状态当作测试基线。
2. **进入战斗地图**：打开 `/Game/Maps/MainMap`，检查 World Settings 中的 GameMode Override 和该模式使用的 Default Pawn Class。确认生成的是 `BP_BrokenEdgeCharacter` 或 `BP_BrokenEdgeCharacter1`，等待比赛进入可操作状态。
3. **检查基础输入**：点击游戏窗口获取焦点，测试 WASD、鼠标转向、空格、左 Ctrl。走近一把步枪，按 E 装备。
4. **第三人称换弹**：记录弹匣和备弹数量，射击数发，按 R，等换弹完成。确认动画、弹药数和再次开火均正常。
5. **第一人称换弹**：按 V，确认身体和手臂可见、头部不挡镜头；重复射击、R 换弹、右键瞄准、蹲伏和跳跃。再按 V，确认第三人称恢复。
6. **两人联机**：按第 2 节启动一台专服和两个客户端。A、B 分别执行上面步骤，再互相观察换弹动作、视角切换时的外观、受伤与死亡重生。
7. **检查日志并记录**：没有新增的蓝图运行时错误、`Combat` 属性缺失、旧热重载类型引用或持续网络错误。把结果填入第 11 节模板。

任一步失败，先记录失败条件，再按第 10 节定位。不要只重试一次成功就勾选通过，也不要通过强行清除换弹状态来掩盖问题。

在项目根目录查看版本：

```powershell

git rev-parse --short HEAD
git status --short
```

当前工作区存在未提交改动，因此只记录提交号不足以唯一识别被测版本，还应保存本轮改动清单或补丁。

### 2.2 冷启动编译

保存并关闭本项目的 Unreal Editor 后，在项目根目录运行：

```powershell
$engineRoot = 'C:\UnrealProjects\UnrealEngine-5.5.4-release'
$projectFile = Join-Path (Get-Location) 'BrokenEdge.uproject'
& '.\Scripts\Assert-EditorClosed.ps1' -ProjectFile $projectFile
if ($LASTEXITCODE -ne 0) { throw '请先保存并关闭本项目编辑器。' }
& "$engineRoot\Engine\Build\BatchFiles\Build.bat" BrokenEdgeEditor Win64 Development "-Project=$projectFile" -WaitMutex -NoHotReloadFromIDE
if ($LASTEXITCODE -ne 0) { throw '构建失败，请先检查编译日志。' }
```

引擎路径是本机当前安装路径，其他机器需替换。正常增量编译即可，不要求每次全量重建。编译成功后重新打开项目，再开始测试。

近期曾出现：增加角色输入属性后，热重载留下 `HOTRELOAD_BrokenEdgeCharacter_0` 引用，动画蓝图报 `Combat` 属性缺失，换弹完成链路受阻。重启后的排查已观察到 `FinishReloading()` 被命中，但这不等于所有武器、网络模式和弹药同步均已通过。

### 2.3 分层执行矩阵

| 层级 | 配置 | 主要目的 | 何时执行 |
|---|---|---|---|
| M0 | 1 个玩家，Standalone，战斗地图 | 输入、相机、动画、基本战斗 | 每次相关修改后 |
| M1 | Listen Server，2 个玩家 | 对比主机玩家与远端玩家的行为 | 修改战斗、复制、命中判定后 |
| M2 | Dedicated Server，2 个客户端 | 验证没有本地玩家的服务器也能完成战斗与同步 | 每次战斗功能验收 |
| M3 | 独立服务器与独立客户端进程 | 排除单进程 PIE 掩盖的生命周期和联网问题 | 提交候选版本前 |
| M4 | 同一构建的 Development 打包服务端和客户端 | 验证 Cook 资产、配置、地图与真实启动流程 | 发布候选版本前 |

PIE 配置入口为编辑器 Play 按钮旁的设置菜单及高级设置。以下为要达到的配置状态，具体中文标签以当前编辑器显示为准：

- M0：Number of Players 为 1，Net Mode 为 Standalone。
- M1：Number of Players 为 2，Net Mode 为 Play As Listen Server。主机窗口和客户端窗口都要测试，不能只测主机。
- M2：Number of Players 为 2，Net Mode 为 Play As Client，并启用独立专服选项（可能显示为 Launch Separate Server）。结果必须是一个专服和两个客户端，而不是两个互不联网的单机世界。
- M1、M2 初次排查可启用 Run Under One Process，方便同一调试器观察不同世界；通过后再做 M3。

**角色和网络身份必须核实**：独立专服没有可操作角色窗口；以 `GetNetMode()`、`HasAuthority()`、`IsLocallyControlled()` 和 PIE 世界名称区分身份。一个窗口不能被同时当作客户端和专服测试证据。

直接从 `MainMap` 启动用于测试战斗；房间搜索、准备和切图必须从 `Lobby` 测试。当前大厅的自动开局实现面向 Dedicated Server，M1 的战斗测试不代表大厅支持 Listen Server 主持房间。

### 2.4 测试数据

准备步枪、霰弹枪各一把；有条件时再覆盖狙击枪和投射物武器。记录实际 `MagCapacity`，不要假设所有步枪都是 30 发。

需要“备弹不足”“无备弹”等条件时，优先通过射击、换弹和拾取建立条件。若为节省时间使用临时测试蓝图、调试器或 PIE 数据修改，必须记录修改值，不保存进正式资产，并在下一轮重建干净的 PIE 会话。

## 3. 输入测试

当前角色输入由 `IMC_CharacterDefault` 和对应 InputAction 管理。实际资产以本轮编辑器显示为准。

| 用例 | 按键 / 动作 | 操作 | 通过标准 |
|---|---|---|---|
| IN-01 | WASD / `IA_Move` | 前后左右、斜向移动，同时转动鼠标 | 方向正确；松开后停止输入；两种视角均可移动 |
| IN-02 | 鼠标 / `IA_Look` | 水平、垂直转向 | 两种视角均响应，无切换后的异常翻转或锁死 |
| IN-03 | Space / `IA_Jump` | 跳跃并移动；松开按键 | 跳跃、落地正常；持枪姿态没有新增异常 |
| IN-04 | LeftControl / `IA_Crouch` | 连续切换蹲伏 / 站立 | 胶囊、移动和镜头高度恢复正确 |
| IN-05 | E / `IA_Equip` | 走近武器拾取；有双武器时离开拾取范围再按 E | 拾取与主副武器切换按场景分别触发，无误换或重复装备 |
| IN-06 | R / `IA_Reload` | 弹匣未满、有备弹时按 R | 进入换弹链路；完整验收见第 4 节 |
| IN-07 | G / `IA_Drop` | 装备后丢弃，再让另一玩家拾取 | 本地和服务器所有权、附着和弹药状态一致；当前属于重点风险项 |
| IN-08 | 鼠标左右键 / `IA_Fire`、`IA_Aim` | 按下、长按、松开 | 开火和瞄准能开始也能结束；失去窗口焦点后不应持续卡在开火状态 |
| IN-09 | V / `IA_ToggleCameraView` | 短按一次；长按两秒；释放后再按 | 每次新的按下只切换一次；长按不连续来回切换 |
| IN-10 | 输入上下文 | 大厅准备、切入战斗、死亡重生后分别检查 | 大厅 UI 可点击；进入战斗后恢复游戏输入；没有重复绑定导致一次按键执行两次 |

若 V 正常但 R 不工作，分别检查 `ReloadAction` 与 `ToggleCameraViewAction` 的蓝图引用；不能用一个按键的成功证明整个 IMC 正常。

## 4. 换弹与武器战斗测试

### 4.1 必做：步枪换弹完整链路（RL-01，P0）

前置条件：比赛处于可操作状态，未持旗，装备步枪，弹匣未满且有备弹。M0、M1 主机、M1 远端客户端、M2 客户端都要执行；每种身份各测第一和第三人称。

1. 记录弹匣 `M0`、容量 `C`、该武器类型备弹 `R0`。暂停自动开火，不同时拾取弹药。
2. 按 R 一次，观察本地换弹动作；由另一玩家观察远端动作。
3. 等换弹完成，再记录 `M1`、`R1`，检查 HUD 与实际武器状态。
4. 再开一枪，确认没有卡在换弹状态；记录这次射击扣弹后的数值，避免与第 3 步混淆。
5. 连续重复三次，覆盖完整的“射击 → 换弹 → 再射击”循环。

没有同期射击或拾取时，应满足：

```text
装填量 A = min(C - M0, R0)
换弹后 M1 = M0 + A
换弹后 R1 = R0 - A
M1 + R1 = M0 + R0
```

例如仅作为测试数据：容量 30、弹匣 23、备弹 40，换弹后应为弹匣 30、备弹 33。实际武器容量不同就重新计算。

通过标准：服务器正确扣备弹、加弹匣；所属客户端最终数值一致；HUD 不多加或少减；换弹状态解除；随后可正常开火。其他玩家不必获得 A 的备弹数，因为 `CarriedAmmo` 使用 `COND_OwnerOnly` 复制。

### 4.2 换弹边界与组合操作

| 用例 / 优先级 | 前置条件与操作 | 通过标准 |
|---|---|---|
| RL-02 / P0 | 弹匣已满时按 R | 不消耗备弹，不进入无法退出的换弹状态 |
| RL-03 / P0 | 备弹为 0、弹匣未满，按 R | 不凭空产生子弹；现有弹匣中的子弹仍能射出 |
| RL-04 / P0 | 备弹少于弹匣缺口，按 R | 仅装入现有备弹，备弹最终为 0，没有负数 |
| RL-05 / P0 | 射空弹匣且仍有备弹 | 自动换弹完成，之后能继续射击；不会无限循环重启动画 |
| RL-06 / P0 | 换弹中连续按 R | 一次换弹只结算一次，动画通知不重复加弹 |
| RL-07 / P1 | 换弹前瞄准，换弹中移动、蹲伏或跳跃 | 动作与武器不明显错位；最终弹药、状态正确 |
| RL-08 / P0 | 换弹中按 V；两种切换方向各测三次 | 不打断弹药结算，不重复执行通知，不永久卡住 |
| RL-09 / P0 | 换弹中按 E 或 G | 记录实际是否允许打断；无论是否允许，都不得把弹药结算到错误武器或造成主副武器不同步。允许规则未确认时另标“待设计确认” |
| RL-10 / P0 | 换弹中被击杀，随后重生 | 不操作已销毁武器；重生后状态干净，能重新拾取、开火和换弹 |
| RL-11 / P0 | 霰弹枪有缺口和备弹，执行换弹 | 每次装填通知只加 1 发、减 1 发；装满或备弹耗尽后结束 |
| RL-12 / P0 | 霰弹枪换弹中，已有至少 1 发时开火 | 按当前 `CanFire()` 规则允许开火；后续状态可恢复，无多扣、多加或负弹药 |
| RL-13 / P1 | 步枪换弹中按住开火键至换弹结束 | 当前逻辑会在完成后尝试开火；确认符合武器射击模式，松开后能够停止 |
| RL-14 / P0 | 步枪和霰弹枪切换后分别换弹 | 各自使用正确弹药池和换弹段落，不共享错误的备弹或容量 |

## 5. 第一 / 第三人称专项测试

当前实现复用原身体资产和最终动画姿势，创建仅所属玩家可见的 `FirstPersonBody` 显示组件，并在该组件上隐藏 `head`。原网格继续承担武器插槽、动画通知和命中判定。第一人称相机默认沿视线水平朝向向前偏移 10 厘米，可在角色蓝图中调整。

| 用例 / 优先级 | 操作 | 通过标准 |
|---|---|---|
| CAM-01 / P0 | 第三人称 → V → 第一人称 → V → 第三人称 | 视角正确切换；恢复原第三人称相机位置和控制方式 |
| CAM-02 / P0 | 第一人称低头、抬头、水平转向，手持步枪 | 身体和手臂在视野覆盖范围内可见；头部不挡镜头；无双重身体 |
| CAM-03 / P1 | 第一人称蹲起、跳跃、落地和贴墙转向 | 眼高变化合理，无持续穿墙观察、明显闪烁或相机漂移 |
| CAM-04 / P0 | 第一人称开火、换弹、换枪 | 显示身体的手部姿势与实际武器插槽同步；换弹通知仍来自原动画链路 |
| CAM-05 / P0 | A 切第一人称，B 观察 A | B 仍看到 A 的完整角色；A 的切换不改变 B 的相机 |
| CAM-06 / P0 | B 分别射击处于两种视角的 A 的头和身体 | 切换视角不改变命中盒或伤害规则；头部仍可被命中 |
| CAM-07 / P1 | 瞄准中切视角；狙击镜开启 / 关闭后再切 | FOV、镜头控制和瞄准 UI 能恢复，不残留错误缩放 |
| CAM-08 / P0 | 第一人称死亡、重生或离开当前角色 | 正常恢复或移除显示组件；新角色默认第三人称，除非产品设计以后明确修改 |
| CAM-09 / P1 | 连续切换 100 次，最后停在第三人称 | 不累积显示组件和姿势回调；第一人称时一个显示组件，第三人称时无残留；帧率、内存无持续恶化趋势 |

现有第三人称动作不等于专门制作的 FPS 动作：某些姿势下手臂可能自然离开镜头范围。测试要区分“视锥之外”“被近裁剪面裁掉”“模型被隐藏”和“姿势不同步”，不要把它们都归因于输入失效。

两个角色蓝图分别使用不同模型和换弹资产，应分别执行 CAM-01～CAM-04、RL-01。仅测 `BP_BrokenEdgeCharacter1` 不能证明 Muriel 角色效果相同。

## 6. 联机同步、伤害与比赛流程

A、B 表示两个客户端玩家；S 表示专服。每个关键用例至少交换一次操作方。

| 用例 / 优先级 | 操作 | 通过标准 |
|---|---|---|
| NET-01 / P0 | M1 中主机开火，再由远端客户端开火 | 两种身份均正确扣弹和伤害，没有重复播放或重复结算 |
| NET-02 / P0 | M2 中 A 换弹，B 观察；之后交换 | S 完成权威弹药结算；所属客户端收敛到正确数值；观察者动画正常 |
| NET-03 / P0 | A 高速移动 / 跳跃，B 射击 | 记录命中与服务器倒带表现；同一发射击不能重复伤害；误差超出测试标准则记录视频和网络参数 |
| NET-04 / P0 | A 第一人称，B 第三人称；互射、死亡、重生 | 视角仅影响本地显示，不改变可受伤性、计分或重生 |
| NET-05 / P1 | 已有人进入战斗后加入新玩家 | 若会话允许加入：角色、比赛阶段、HUD、装备状态正确；若拒绝：清晰提示，不留半连接状态。中途加入策略需在测试记录中明确 |
| NET-06 / P0 | 玩家在换弹 / 换枪 / 死亡过程中断开 | 剩余玩家继续游戏，服务器不崩溃，不保留无效角色引用；重新加入按当前产品策略测试，不假设自动断线重连已实现 |
| MATCH-01 / P0 | Teams 中分别攻击同队、敌队和自己 | 当前代码对同队其他玩家伤害为 0，自伤不按友伤屏蔽；敌人伤害按武器配置结算 |
| MATCH-02 / P0 | 完成一局：预热 → 战斗 → 冷却 / 重开 | 各端阶段与倒计时一致；受限阶段不能继续有效开火；下一局状态无残留 |
| MATCH-03 / P1 | 连续进入 / 退出队伍，击杀不同队伍玩家 | 队伍成员、得分和击杀归属一致；异常击杀、自伤计分另立用例确认规则 |

源码默认预热 / 比赛 / 冷却为 10 / 120 / 10 秒，但蓝图可以覆盖；以本轮实际 GameMode 配置为准。等待阶段未结束导致的 `bDisableGameplay` 不应误判为按键失效。

[Known_Issues.md](Known_Issues.md) 曾记录 Listen Server 主机爆头判定异常。这是历史问题线索，当前是否仍存在须执行 CB-04、NET-01 后确认；不得仅因已有记录而忽略回归。

### 7.2 直接复用现有脚本

项目已有 [Test-LanSessions.ps1](../Scripts/Test-LanSessions.ps1) 和 [SessionLobbyTests.cpp](../Source/BrokenEdge/Tests/SessionLobbyTests.cpp)，测试名为 `MultiplayerSessions.LAN.MenuFlow`。

在项目根目录执行。脚本默认引擎路径与本机当前安装不同，因此显式传入 `-EngineRoot`：

```powershell
# 无渲染：房间搜索、准备、取消准备、跳图等逻辑测试
.\Scripts\Test-LanSessions.ps1 -EngineRoot 'C:\UnrealProjects\UnrealEngine-5.5.4-release'

# 额外验证大厅切换模式
.\Scripts\Test-LanSessions.ps1 -EngineRoot 'C:\UnrealProjects\UnrealEngine-5.5.4-release' -SwitchMode

# 启用离屏渲染并输出界面截图
.\Scripts\Test-LanSessions.ps1 -EngineRoot 'C:\UnrealProjects\UnrealEngine-5.5.4-release' -Render
```

每条命令是独立的一轮测试，按需执行。开始前退出其他本项目 LAN 测试服务器，避免“空列表”“发现两个房间”等前置条件被外部进程影响。多网卡机器可按脚本参数传入 `-BindAddress`，值应为本机实际 IPv4 地址。

结果位于 `Saved/SessionTests/Dedicated-<时间戳>/`。检查脚本退出状态和每个参与进程的日志，不只看某一个 `PASS`。重点证据包括 `SESSION_FLOW_OK`、`READY_CANCEL_AND_RETRY_OK`；模式切换测试还有 `MODE_SWITCH_OK`。

边界：该脚本验证大厅流程，**不覆盖 R 换弹、V 切视角、开火伤害或 FPS 表现**。默认 `-nullrhi` 运行不能证明视觉效果正确。不要直接在普通编辑器会话里点运行该测试名，因为测试要求脚本提供服务器和客户端角色参数。

## 8. 弱网测试

先通过正常网络下的 M2，再打开 PIE 高级设置中的 Network Emulation。每轮明确模拟作用于服务器、客户端还是双方，并记录设置截图。参数是模拟配置，不直接等同于最终往返延迟；以实测 RTT / Ping 为准。

| 档位 | 建议注入条件 | 必测用例 | 观察重点 |
|---|---|---|---|
| W0 | 无模拟延迟、无丢包 | RL-01、CAM-05、NET-02 | 建立正常网络基线 |
| W1 | 约 100 ms 延迟、0% 丢包 | RL-01、RL-05、RL-08、NET-02 | 本地预测与服务器最终结果一致，不重复扣弹 |
| W2 | 约 100 ms 延迟，波动范围约 ±20 ms，1% 丢包 | RL-06、RL-09、NET-03 | 快速组合输入下状态能恢复，命中与动画表现可解释 |
| W3 | 约 200 ms 延迟、5% 丢包 | RL-01、RL-10、NET-06 | 无崩溃、无永久卡换弹；网络恢复后状态收敛 |

每档至少完成 10 次换弹和 10 次武器切换。记录“按键到本地动作”“动画结束到弹药最终一致”的时间，以及当时帧率。可将稳定网络恢复后 5 秒仍不一致设为本轮排查触发阈值，这是建议测试阈值，不是现有实现保证或最终产品指标。

暂停调试器会冻结同进程服务器和客户端，不能用这种暂停测网络延迟或操作手感。结束后关闭网络模拟，释放测试注入的输入，并重建一次正常网络会话复测。

## 10. 换弹失败时的定位顺序

### 10.1 从最早失效的一步查起

```text
R 键 → IMC_CharacterDefault → IA_Reload → ReloadButtonPressed()
    → UCombatComponent::Reload()
    → ServerReload() / HandleReload() → PlayReloadMontage()
    → AnimBP 的换弹通知 → FinishReloading()
    → 服务器 UpdateAmmoValues() → 武器 AddAmmo() → 客户端同步与 HUD
```

这是普通武器的排查顺序；霰弹枪逐发装填另走 `ShotgunReloadOnce()` / `UpdateShotgunAmmoValues()`。本地预测与服务器执行并不是一条单线程同步流程，要分别记录实例和网络身份。

| 症状 | 最先检查 | 关键证据 |
|---|---|---|
| 按 R 完全无反应 | `ReloadButtonPressed()` 是否命中；窗口焦点；IMC 是否添加；蓝图 `ReloadAction` 引用 | 不能仅检查 `DefaultInput.ini`；此功能使用增强输入 |
| 命中输入函数但不进入换弹 | `bDisableGameplay`、`bHoldingTheFlag`；`Reload()` 条件 | `CarriedAmmo > 0`、状态为空闲、已装备、未满弹匣、`bLocallyReloading == false` |
| 状态变为换弹但没动作 | `ReloadMontage`、当前 AnimInstance、武器段落、Slot 接线 | `PlayReloadMontage()` 是否真正播放；步枪段 `Rifle`，霰弹枪段 `Shotgun` |
| 有动作但不加子弹 | `FinishReloading()` 是否由动画通知调用；服务器是否也到达 | 不只看拥有者客户端；S 上 `Character` 和 `EquippedWeapon` 必须有效 |
| 只能换第一次，后面无反应 | 换弹状态是否复位；通知是否丢失 / 被打断 | `bLocallyReloading` 和 `CombatState`，与通知时间对应 |
| 第一人称失败、第三人称正常 | 原网格动画是否继续更新；显示身体是否仅复制姿势 | 不能把弹药通知转移到无独立 AnimInstance 的显示组件上 |
| 服务器正确、HUD 错误 | `AddAmmo()`、客户端弹药同步、`OnRep_CarriedAmmo()`、HUD 更新 | 分别记录服务器弹匣、所属客户端弹匣和显示文本 |
| `Combat` 缺失或旧类型报错 | 最近是否热重载修改了角色反射布局 | 搜索 `HOTRELOAD_BrokenEdgeCharacter`、`Forged object`、`缺失的属性`；保存并冷启动编译后重测 |

### 10.2 调试器最小证据集

先设置 `ReloadButtonPressed()` 和 `FinishReloading()` 两个断点，避免一开始在每帧函数上停住。每次暂停记录：

- 当前函数、调用栈、角色名称、所在 World、网络身份。
- `CombatState`、`bLocallyReloading`、`CarriedAmmo`。
- `EquippedWeapon`、`Ammo`、`MagCapacity`。
- `ReloadMontage`、当前 AnimInstance、第一人称状态。

只有确认某个阶段没有到达，再向前补断点。服务器和客户端都可能命中同一行；`FinishReloading()` 命中一次不代表两端都完成。测试结束移除临时断点，保留测试前已有的用户断点。

### 10.3 日志与画面

编辑器日志位于 `Saved/Logs/`；独立进程测试为每个进程保存单独日志。一次失败至少提供操作方视频、另一个客户端画面和服务器日志，时间点尽量对齐。

在项目根目录搜索本轮编辑器日志：

```powershell
Select-String -Path '.\Saved\Logs\BrokenEdge.log' -Pattern 'HOTRELOAD_BrokenEdgeCharacter|Forged object|缺失的属性|Blueprint Runtime Error|Fatal error|Ensure condition failed'
```

先备份失败日志，再重启编辑器，避免日志轮换后丢失证据。若使用输入注入测试，结束必须释放注入键；不要把持续注入的开火键误认为游戏输入卡住。

### 11.2 优先级

- **P0**：阻断核心功能或影响公平性，例如不能换弹、重复加弹、穿墙伤害、视角切换改变命中判定、服务器崩溃。发布候选版本不得遗留未处理的 P0。
- **P1**：明显影响体验或稳定性，例如特定动作穿模、HUD 恢复异常、长时间运行退化。记录复现范围、影响和处理决定。
- **P2**：轻微视觉或界面问题。保留可复现记录，不与核心状态错误混在一起。

环境没有准备好属于“阻塞”，不是“通过”。产品规则尚未确定属于“待设计确认”，不能为了让测试通过而把当前偶然行为直接定为需求。

### 11.3 本次改动的最低验收门槛

- RL-01～RL-06、RL-08、RL-10、CAM-01、CAM-04～CAM-06 在 M0 和 M2 完成；涉及远端行为的用例在 M2 验证。
- 两种角色蓝图和步枪、霰弹枪都有对应记录；不能只测一把武器。
- R 换弹与 V 切换各连续执行至少 20 次，未出现丢绑定、重复触发或状态锁死。
- 至少完成一轮 W1 弱网换弹验证，并在关闭弱网后再次通过正常网络用例。
- 没有新增的蓝图属性缺失、旧热重载类型引用、崩溃或持续网络错误。
- 发布打包版本前，额外通过 M3 / M4 的房间进入、战斗换弹和视角切换测试。

本次文档编写只核对了现有源码、脚本和此前排查证据，没有执行上述完整测试矩阵，也没有重新打包游戏。
