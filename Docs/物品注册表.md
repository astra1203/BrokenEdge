# 物品注册表

`/Game/Extraction/Registry/DA_ItemRegistry` 是 `UExtractionItemRegistry` Primary Data Asset，登记 367 个稳定 ID 到物品定义软引用。存档仍保存 ItemId，资产目录/文件名可变化；新增物品需更新 Entries，并保持定义自身的 ItemId 与键一致。`ValidateEntries` / `IsDataValid` 会报告空表、空 ID、缺失引用和身份不匹配。

`UExtractionItemDefinition::Get` 优先查表，登记项损坏或身份错误直接返回空。只有没有登记且属于旧白名单的 ID 才尝试旧目录，并按 ID 记录一次 Warning；未知 ID 不拼接任意路径。`Ids()` 由注册表生成并按名称排序，首次加载后为进程生命周期快照；编辑注册表后重启测试进程。新排序可能改变同一旧随机种子的掉落抽样结果，存档中的物品身份和数量不变。

注册表建立时展开完整 ExtractionCollectibles.inl，未改动原有物品定义。一次性创建入口 `item-registry-create` 拒绝覆盖已有注册表；日常编辑后运行 `item-registry-export` 校验并更新 `Config/ExtractionItemRegistry.json`。导出包含真实资产 SHA-256，纯 Python 检查拒绝过期导出，不解析 uasset 猜测数据。

```powershell
python Scripts/Extraction/run_editor_task.py item-registry-export --engine <UE根目录> --tag <唯一名>
python Scripts/Extraction/run_editor_task.py item-registry --engine <UE根目录> --tag <唯一名>
python Scripts/Extraction/check_runtime_cook_coverage.py --json
python Scripts/Extraction/check_runtime_cook_coverage.py --cooked-content <Cook输出的平台/项目/Content目录> --json
```

检查分四阶段记录：源资产存在、Cook 目录规则、可选的松散 Cook 输出、包内 Client/Server 实际进图开背包。最后一阶段必须单独运行；编辑器全量加载不等于包内验证。当前前两阶段通过，后两阶段未执行；输出始终明确 `all_four_stages_passed=false`，不能将纯 Python 的 PASS 当作打包验收通过。IoStore/pak 文件不能直接作为松散 Cook 目录传入。

当前资产目录与 AlwaysCook 保留兼容；资产搬到新目录后需更新 Cook 规则和导出。检查也读取地图注册表的配置路径，补上输入映射目录的 AlwaysCook。生成器覆盖保护及剩余边界见 [生成资产清单](生成资产清单.md)。
