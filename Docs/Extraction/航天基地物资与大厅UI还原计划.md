# 航天基地物资与大厅 UI 还原计划

整理日期：2026-10-24
调查基线：`ca52fad0`
状态：阶段一持刀修复已完成本轮构建、PIE 与双渲染回归；阶段二进行中，其余阶段未完成。

## 1. 目标、基准与交付范围

修复持刀切换第一／第三人称后刀不跟随和握柄不贴合的问题，恢复航天基地的物资点位及候选点随机刷新，建设接近参考版本的烽火地带大厅与局内 UI，并建立官方功能差距清单。

已确认的选择：

- 以 `D:\司晨\源代码和素材\三角洲解包资产` 的本地资料为基准。提取说明更新于 2026-09-30，该时间不是已确认的游戏构建号，不宣称与当前正式服一致。
- 大厅以烽火地带完整出战流程为范围；全面战场等其他模式仅进入差距清单。
- 物资摆放位置优先，掉落概率可以使用项目配置。允许兼容补齐，但必须标注来源与缺口。
- 用户明确指出部分大保险在两三个候选位置中随机出现一个。实现互斥候选组；具体哪些点属于同组仍需数据核实，不能把所有大保险都一律套成同一规则。
- 保留现有库存、经济、服务器权威、存档及枪械系统；不把已完成的枪械工作重新列为待开发。

证据分为“来源确认”“推断”“项目兼容”“待核实”；实现状态另外记录为“未实施”“已实施待验收”“已验收”。来源确认不代表运行通过，模型存在不代表点位或规则已还原。

本计划关联[枪械系统完善计划与实施进度](枪械系统完善计划与实施进度.md)和[航天基地搜打撤体验差距与实现方案](../航天基地搜打撤体验差距与实现方案.md)。旧方案中的状态须以当前代码与证据更新后使用。

## 3. 阶段一：持刀生命周期、握姿与动作

### 实施

1. 为近战表现建立统一刷新入口，由视角切换、手臂重建、持刀状态复制及装备变化触发。检查组件有效性、注册状态和父组件身份；旧手臂销毁前清理绑定，再按当前视角重建或重绑。Tick 只作必要兜底，避免每帧反复创建。
2. 分离第一／第三人称模型、挂点和握持变换配置。先校验骨骼、比例、导入轴向与握柄参考点，再用握持参考变换对齐；分别调整手腕和手指握姿，不能仅移动整把刀掩盖错误重定向。
3. 为第三人称补齐持刀待机、移动及攻击状态，检查第一人称手臂显示条件，避免持刀时仍依赖当前枪械是否存在。
4. 用服务器攻击开始时间、攻击类型及现有冷却状态同步表现。攻击中途切视角时恢复新视角的动画进度，不重置攻击、不重复伤害；缺少对应动画时回退至有效持刀姿势。
5. 倒地、死亡、攀爬、切枪和 EndPlay 清理攻击定时器、隐藏状态及表现组件。保留服务器命中裁定；距离、伤害和时序继续标为兼容参数。

### 接口与验收

- 近战组件新增表现刷新与动作恢复接口，分离视角握持配置；若新增复制的攻击表现状态，仅传攻击类型、序列及时间，不由客户端提交命中结果。
- 连续切换视角 30 次，覆盖待机、移动、轻／重攻击中途、切枪、攀爬及死亡。
- 两名渲染客户端检查持有者与旁观者：无冻结、悬空、重复刀；手掌包住握柄，手腕无明显扭折；攻击不重复结算。
- 保存固定机位的握姿截图和切换录像／连续帧。静态检查或无渲染测试不替代视觉验收。

## 4. 阶段二：物资点位与互斥随机刷新

### 4.1 点位取证与转换

沿用 `Scripts/Extraction/inspect_source_gameplay.py` 与地图转换器的解析能力，另建只读物资调查流程。解析物资 Actor、生成器、组件父级、蓝图默认值、引用表与地图变体；记录归档内路径、文件哈希、对象／导出索引、原始坐标、旋转、缩放及引用链。

分别确认大保险、小保险与其他容器，关联模型、交互方式、开箱动画、搜索时长与钥匙门。通过 `SourceToWorld` 转换到项目地图，逐点验证房间、楼层、墙体和实际可达性；不得用统一向下射线把楼上点位吸到楼下。对尚未恢复的建筑空间记录阻塞原因，不把原点位随意挪到附近路边。

点位与刷新组按地图变体隔离。`Level1/Level2/Ma1` 等命名不能未经验证直接映射为某个玩家可见难度。

### 4.2 数据与运行时规则

- 地图定义增加物资点与刷新组：稳定点 ID、容器类型、变换、地图变体、组 ID、来源及证据状态。
- 容器类型定义模型、交互和掉落池引用；掉落池与点位分开，兼容概率不能污染点位来源记录。
- 刷新组定义候选点 ID、选取数量与权重。已确认二选一／三选一组设置选取数量为 1；缺失权重默认等权，明确标为项目配置。
- 服务器在一局初始化时用该局种子抽取并保存结果；区域加载只实例化已选中的容器，不重新抽签。客户端不自行随机，后加入者获得同一结果。
- 容器身份和内容在本局内稳定，搜索、关闭 UI、离开区域和重新加载均不能补货。下一局重新生成；复用现有权限过滤与库存事务。
- 验证重复点 ID、空组、非法候选引用、跨变体引用及选取数超过候选数；非法组禁止生成并输出具体诊断。

### 4.3 缺失信息处理

优先追查生成器引用、关卡关联和蓝图默认值来确定候选关系，不能仅凭两点靠得近就认定是同组。确实缺失时允许项目兼容候选组，但必须记录哪些坐标可验证、哪些关系是推断。用户强调点位准确性，因此未查明的坐标保留待核实，不能把随意摆放记为官方点位完成。

交付点位清单、候选组示意图、来源索引、缺失列表和逐点截图。数量以解析结果为准，不预设一个虚构的“官方保险柜总数”。

### 验收

- 固定种子可复现；批量种子测试每组数量、互斥性及合法候选覆盖；等权兼容组单独标识。
- 所有启用点位均可到达和交互，不穿墙、不浮空、不跨楼层。
- 多人并发搜索和拿取、后加入、区域卸载重载后，选择结果、内容与容器身份一致，无重复领取。
- 大保险候选组以实际关卡截图验证“多个候选点只激活一个”，不仅检查随机函数。

## 5. 阶段三：烽火地带大厅与统一 UI

### 页面和视觉基准

建立本地解包素材目录和逐页对照表，记录图标、字体、背景、布局、间距及状态。缺少同版本完整画面时以统一项目布局补齐并标注，不用单张图集宣称像素级还原。

大厅使用独立三维角色／小队展示对象，包含玩家状态、地图选择、仓库配装、商店任务及准备出战区。展示预览不得修改实际库存。地图和变体只启用已有可运行内容；现有其他模式保留原入口，不借本轮伪装成官方完整模式。

统一仓库、出战配装、背包搜索、物品详情、改枪、HUD、地图、死亡观战及撤离结算。物品格复用现有网格交互，补充图标、品质、尺寸、数量和状态；统一加载、等待、失败、物资被他人取走、取消与返回的反馈。

### 接口与行为

- UMG 负责页面组合，复用现有 Slate 网格交互；规则、价格、资格和库存变更仍来自既有服务端接口。
- 物品展示字段进入定义或展示配置；避免把贴图、字体等表现数据写入每个存档实例。
- 队伍与准备状态读取现有复制状态；预览不提交事务，应用或出战才走现有授权请求。
- 地图底图与世界坐标共用转换，核验楼层、队友和撤离标记。未实现业务不提供看似可操作但无效的按钮。
- 打通大厅→配装→准备→出战→死亡或撤离→结算→返回大厅；正确显示返回后的装备和仓库变化。

### 验收

在 1280×720、1920×1080、2560×1440 及一种超宽比例验证关键内容、长名称、空包、满包、拖放和焦点；关闭页面后输入恢复正确。单人和组队走完整流程，覆盖准备取消、库存变化及服务器拒绝。每页保存参考与项目截图，记录具体差异，不以主观还原度百分比代替验收。

### 阶段一结果（2026-10-24）

- 第一人称手臂销毁前释放刀组件；视角重建后校验并重建父子绑定。重击中的新手臂按第三人称蒙太奇进度恢复动画，伤害定时器不重新触发。失去行动能力时清除待执行攻击。
