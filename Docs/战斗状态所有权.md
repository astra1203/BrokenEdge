# 战斗状态所有权

WP-13 按实施方案的默认决定保留并冻结旧 Combat 模式。适配器负责模式分流，RPC 校验和预测协议继续由原组件执行。

## 当前边界（第五阶段）

| 状态 | 旧 Combat | Extraction | 复制/完成 |
| --- | --- | --- | --- |
| 按住开火 | Combat 的 `bFireButtonPressed` | ExtractionCombat 的 `SprintFire.FireHeld` | 本地输入；Extraction 通过本组件可靠 RPC 同步服务器，远端不维护按键 |
| 动作状态 | Combat 的 `CombatState`，由旧换弹/切枪/逐发装填逻辑持有 | ExtractionCombat 的 `ActionState`，只由自身服务器入口/定时器写入 | 各自组件的属性服务器 → 所有客户端；统一通过模式适配器查询，互不覆盖 |
| 本地换弹预测 | Combat `bLocallyReloading` | ExtractionCombat `bReloadPredicted` | 不复制；适配器查询当前模式，Extraction 拒绝回执/取消/EndPlay 仅清理自身预测 |
| 弹匣权威值 | Weapon Ammo，Combat 装填 | Inventory 物品实例，射击后 RecordShot、装填事务 Reload；Weapon 是战斗快照 | Extraction 同组件可靠回执校正拥有者，Multicast 更新观察者 |
| 备弹 | Combat `CarriedAmmoMap` | Inventory 物品数量 | Combat `CarriedAmmo` 为 HUD/旧调用兼容快照，仅拥有者复制 |
| 射击计时器 | Combat `FireTimer/bCanFire` | ExtractionCombat `FireCooldownTimer/bFireCooldownReady` | 两模式独立；Extraction 仍由 NextShotTime 校验服务器射速，SprintFire 控制跑射门槛 |
| 换弹计时器 | 动画通知驱动 | ExtractionCombat `ReloadTimer` | 服务器独占，新模式动画通知不能移弹 |
| 切枪计时器 | 动画通知驱动 | ExtractionCombat `SwapAttachTimer/SwapFinishTimer` | 服务器校验开始时的双武器引用，挂接/结束各一次 |

输入第一步让 Extraction 不再回写旧模式按键字段，所有连射读取当前模式的输入状态。取消通过 Combat 自己的方法清理旧输入残留，避免友元跨组件写字段。`ICombatModeAdapter` 的 Reload、FinishReload、Drop、SetFireHeld、CancelFire 将这几项入口的模式选择集中在一处。

第二阶段将 CanFire、StartFireTimer 和换弹预测访问也交给适配器。旧霰弹枪允许逐发装填中断的判定留在旧模式；Extraction 使用本模式的行动、冷却、预测及权威 CombatState 检查。动画继续通过 Character → Combat 查询当前模式的换弹预测，原有 RPC 签名和复制属性不变。

Extraction 冷却以发起时的武器弱引用为上下文：到时先解除本模式冷却，再确认原武器仍是当前武器、模式有效且角色可行动，才允许连射/空仓换弹。旧武器的定时器不对替换武器执行动作；旧模式回调也不驱动 Extraction。EndPlay 清除自身冷却和换弹定时器及预测标记。取消按键不提前解除射速冷却。

第三阶段移除 `PublishExtractionCombatState`，新模式不再读写旧复制字段。`SetActionState` 为 ExtractionCombat 私有权威入口；客户端取消只清理本地预测，动作状态等待服务器复制。`OnRep_ActionState` 驱动远端换弹与切枪完成标记，旧 Combat 的 RepNotify 在新模式下不触发表现。Character、动画、交互和装备挂接通过当前模式查询状态；旧模式的本地切枪预测也收回 Combat 适配器。

新增的复制属性属于网络布局变更，服务器与客户端应一起更新。任务/库存持久化格式和资源资产未改变。所有状态变化仍经过原有动作校验和库存事务，不由动画通知提交 Extraction 弹药。

第四阶段将死亡/丢枪的动作清理收敛到适配器 CancelActions：旧模式清理输入、换弹预测、切枪挂接许可和射击计时器；Extraction 调用自身取消入口。旧霰弹枪逐发通知必须处于权威换弹状态且有备弹/弹匣空间，结束通知不再批量补弹；旧切枪挂接每次只允许一次，迟到的结束通知不能解锁后续换弹。服务器 Idle 复制同步清理切枪表现标记。

第五阶段让旧模式本地与服务端共用 `CanStartLegacyReload`，过期请求不得覆盖正在进行的切枪；空备弹、满弹匣、死亡/禁用玩法不能发起换弹。切枪与预测还要求双武器有效。新增回归在旧代码复现 9 条失败，修复后 4 项状态测试和 1 项网络回归通过，见 [权威请求校验](Artifacts/TechnicalDebt/WP13/Phase5/README.md)。

## 后续验收与边界

仍有兼容关系：Combat 备弹快照与武器挂接/引用由两模式复用，部分表现及旧 RPC 拒绝新模式的分支继续保留。友伤/射速/弹药/装配版本校验保持在原协议入口。

第三阶段已通过同进程专服 + 双客户端网络 PIE，在各 NetDriver 的 150 ms 发包延迟、5% 丢包配置下验证动作状态复制、拥有者预测/拒绝回执、远端切枪标记及弹药守恒。第四阶段补齐客户端切枪入口、开背包取消换弹、切枪中死亡和掉落守恒，见 [动作中断证据与边界](Artifacts/TechnicalDebt/WP13/Phase4/实施记录.md)。还需覆盖独立进程/打包、大地图与真实大厅、重连，以及旧模式真实地图/联机完整矩阵。单玩家 PIE 与临时 World 仍只计为本地回归证据。
